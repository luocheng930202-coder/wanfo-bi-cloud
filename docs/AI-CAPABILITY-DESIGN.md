# 万佛数据平台 AI 能力设计

> 版本：1.0；日期：2026-11-07；状态：设计基线，尚未实现。  
> 配套：[任务清单](AI-DEVELOPMENT-TASK-LIST.md) · [开发排期](AI-DEVELOPMENT-PLAN.md)。

## 1. 产品目标与边界

建设基于可信数据的分析助手：帮助用户发现资产、理解口径、解读图表，用自然语言查询并保存可编辑图表，随后辅助建模、治理、诊断与大屏制作。

保持“企业自助 BI + 可信批处理入仓 + 轻量治理与数据服务”的产品定位。依照本次用户决策，将原产品定位中“AI Copilot 后置可选”调整为独立建设阶段，不替换查询、安全、指标和数据集底座。本设计不代表已具备生产 AI 能力，不承诺任意问题都能准确回答。

首期采用一个模型提供方、一个智慧食堂业务域、经过认证的指标和数据集。首期不支持任意 SQL 执行、自动修改数据、无人值守发布、自动加工或根因确定性判断。不建设通用 Agent 平台，不训练基础模型。

## 2. 现有能力与复用方式

| 现有能力 | AI 使用方式 | 上线前核验 |
|---|---|---|
| 目录、术语、标准、血缘 | 检索定义、负责人、来源、影响关系 | 可见范围、版本、敏感元数据 |
| 指标、数据集与字段 | 解析业务问题，构造受控查询 | 业务粒度、时间、可加性、关联基数 |
| 数据集计算字段、分组、SQL 参数 | 提供配置草稿及解释 | 保留既有校验，不扩大执行权限 |
| 查询执行、行列权限、并发与超时 | 执行获批的结构化分析请求 | 每次重新授权，取消与限流有效 |
| 图表、看板、模板 | 解读结果，创建图表草稿 | 实际定义版本和保存 API 兼容性 |
| 质量、任务、审计与追踪 | 提示数据可信度，辅助排查 | 数据新鲜度来源、错误信息脱敏 |

代码中存在接口不视为验收通过；开发前通过 SYSTEM-DESIGN、实际 DTO、资源授权和查询入口逐项确认。特别是预算在订单明细中重复出现，必须在语义层标记粒度和聚合限制，不能让模型直接求和。

## 3. 能力分期

| 版本 | 范围 | 交付结果 |
|---|---|---|
| R0 | 模型网关、权限工具、业务语义、评测基线 | 可受控调用、可追溯、可关闭 |
| R1 | 智能找数、口径问答、单图解读 | 带权限和证据的只读助手 |
| R2 | 自然语言问数、多轮澄清、制图 | 智慧食堂分析到可编辑图表闭环 |
| R3 | 数据集建模、治理建议、运维诊断 | 建议与草稿；人工确认后走原流程 |
| R4 | 模板驱动看板/大屏生成、异常辅助分析 | 可编辑布局、绑定与主题；统计证据可查 |

## 4. 逻辑架构与部署

前端助手 → 网关登录鉴权 → AI 编排模块 → 权限化元数据检索/语义解析 → 受控工具 → 现有业务服务。

模型经统一 Provider 接口访问，只负责理解和生成候选计划。工具可用范围由服务端注册表及当前用户权限共同决定。模型不能提交身份、组织范围或覆盖工具授权上下文。

初期在现有 BI 后端内建立独立 ai 包边界，复用平台库、Redis、审计和 Trace；不增加必须独立部署的服务。框架及 SDK 版本在 R0 做当前 Java/Spring/Jackson 兼容性验证后确定，不预先引入重型编排框架或向量库。R1 优先结构化搜索，证明确有召回问题再增加向量检索；向量索引只是派生副本，平台库是权限及资产事实来源。

组件职责：

- ProviderGateway：模型端点白名单、密钥引用、模型能力、超时、熔断、用量计量；禁止任意 URL 代理。
- AiOrchestrator：场景路由、有限步骤状态机、取消、错误分类、证据组装。
- SemanticRegistry：已批准业务域、指标、维度、关系、别名、版本与验证案例。
- AuthorizedRetrieval：在检索、工具调用、结果读取和历史展示时分别复核授权。
- ToolRegistry：类型化输入输出、操作级权限、资源限制、输出脱敏及审计。
- EvaluationService：固定题库、结果比较、越权/攻击测试、版本回归。

## 5. 业务语义设计

不复制既有指标、字段和数据集事实。语义条目引用稳定资源 ID 与版本，只补充 AI 所需信息。

| 对象 | 关键属性 |
|---|---|
| 业务域 | 名称、负责人、授权范围、认证状态、默认时区 |
| 指标语义 | 指标 ID/版本、别名、定义、单位、粒度、聚合限制、分子分母、空值/零分母规则 |
| 维度语义 | 字段 ID、时间语义、行政层级、允许筛选/分组方式、敏感级别 |
| 关系语义 | 两端资源/字段、1:1/1:N/N:N、连接类型、度量膨胀风险、审核状态 |
| 验证案例 | 自然语言、必要澄清项、预期计划、固定数据期望值、权限身份 |

发布流程：草稿 → 校验 → 管理员审核发布 → 冻结版本。底层字段/指标版本变化后标记待复核，相关条目暂停问数；模型生成的说明或关系只能成为草稿。N:N、混合粒度或无法证明安全的跨数据集组合，首期拒绝并推荐已有认证数据集。

“生均餐费”有不同分母，未确定具体指标时先澄清。“同比”需要时间粒度、可比周期和缺期规则。“本月”按服务端业务时区解析成固定起止日期并展示，不能随模型猜测。

## 6. 查询与答案流程

1. 用户提交问题，服务端确定身份和可用业务域，检索最少必要的授权语义。
2. 模型生成有 Schema 的候选计划：业务域、数据集/指标 ID、版本、维度、筛选、时间、排序和行数限制。
3. 歧义或缺少指标时返回澄清问题；不存在数据或不支持的分析明确拒答。
4. 服务端校验计划类型、字段存在性、维度兼容、聚合粒度、参数、版本及权限，再转换为现有查询模型。
5. 通过原查询入口执行，保留行列策略、超时、并发、取消和查询审计。禁止拼接模型 SQL 绕过入口。
6. 对实际结果进行确定性计算与校验，模型基于结果摘要生成解释。数字、排名和比较来自计算结果，不能由模型补写。
7. 返回证据：资源及版本、口径、时间/筛选、实际查询时间、源数据新鲜度（未知时明确未知）、质量状态、查询记录和限制说明。
8. 制图输出通过现有图表 Schema 和字段校验生成草稿。用户确认后调用原保存接口，保存时再授权并检查版本，返回现有编辑器。

运行状态：RECEIVED、RETRIEVING、NEEDS_CLARIFICATION、VALIDATING、QUERYING、GENERATING、SUCCEEDED、FAILED、CANCELLED、EXPIRED。终态不可继续执行工具；重试生成新运行并关联旧运行，写工具有幂等键。断开流连接不等于取消，提供显式取消按钮和服务端截止时间。

首期找数使用 listAssets/getMetricDefinition；图表解读使用 getAuthorizedChartResult；问数使用 executeSemanticQuery；保存使用 createChartDraft。模型无法调用数据库连接、原始凭据、发布、导出或任意 HTTP 工具。

## 7. 界面与用户体验

- 工作台：新增“AI 分析”入口和业务域选择，示例问题来自已验证案例。
- 目录/指标：提供“解释口径”“寻找相关资产”，引用可打开现有详情。
- 图表详情：侧栏解读当前已执行的查询快照，明确当前筛选和快照时间，不默默改变查询范围。
- 分析页：对话、澄清选项、结果表/图、口径与来源、查询状态、取消、保存图表、反馈。
- 管理页：模型连接、出域策略、语义认证、用量预算、运行审计、评测结果。
- R3 在数据集/任务/质量页按场景嵌入；R4 在编辑器生成可编辑组件，保留原作品并提供撤销。

切换话题、业务域或权限身份时重新确定上下文。历史答案标记生成时间，打开时复核资源和数据权限；失权后隐藏内容，不能通过旧对话读取已撤销数据。

## 8. 安全、隐私与运行约束

新增功能权限建议为 bi:ai:use、bi:ai:query、bi:ai:chart、bi:ai:manage、bi:ai:audit；这些权限不代替数据资源权限。管理员查看 AI 审计不自动获得业务数据读取权。当前组织范围复用现有机制，不将未来多租户隔离宣称为已有能力。

元数据、文档和数据内容均为不可信资料，其中的“忽略限制”等文字不得改变工具或身份。结构化校验、工具白名单和授权由服务端强制。拒绝任意 URL、脚本、数据库写入和越权字段；错误响应也不暴露受限资产是否存在。

默认出域策略只允许批准的元数据；查询结果摘要需单独批准，敏感明细禁止出域。未允许结果出域时使用本地确定性摘要或经批准的本地模型，不偷偷发送数据。是否可调用外部模型、留存条款和部署区域是试点前的明确决策项。

建议初始限制（需压测调整）：每轮最多 5 次工具调用、1 次查询修复、候选资源 10 个；结果最多 200 行，发往模型的摘要最多 50 行且受字节上限约束；查询超时取既有上限与 AI 配置较小者，整轮截止 90 秒。单用户活动运行 1 个，初始全局 4 个，不抢占 BI 核心查询保留容量。

配置用户/日、全局/月预算与硬停阈值。调用前预留用量，结束结算，失败也计实际消耗；无精确 token 时估算并标记。缓存必须包含主体/授权指纹、组织范围、语义/资源/策略版本、时间条件和数据新鲜度；无法证明安全时不共享，撤权不依赖缓存 TTL。

默认运行元信息保留 90 天、会话内容 30 天（部署前按合规复核）；原始提示、结果和敏感明细默认不进普通日志。必要内容加密存储、限制访问、可清除，审计只记资源引用、状态、耗时、用量和脱敏错误。Trace 不写明文问题/结果。

## 9. 拟议数据结构与 API

下列为逻辑设计，真实 Flyway 版本在实施时根据仓库最新迁移编号分配；本次不执行建表。

| 拟议表 | 核心内容 |
|---|---|
| bi_ai_provider | 模型配置、密钥引用、出域与限额，不存前端可读明文密钥 |
| bi_ai_semantic_domain / revision | 业务域、不可变版本、审核状态 |
| bi_ai_semantic_binding | 引用现有资源/字段及版本、别名、粒度、允许操作 |
| bi_ai_example | 认证问题、计划与固定期望值、适用版本 |
| bi_ai_conversation / message | 所属主体、场景、内容留存策略、上下文版本 |
| bi_ai_run / tool_call | 状态、证据引用、版本、用量、Trace、脱敏摘要 |
| bi_ai_feedback / evaluation_run | 反馈、评测集版本、通过率与失败原因 |

复用现有审计和配额基础，是否需要额外用量明细表在 R0 评审确认。版本更新使用乐观锁；语义资源失效有可查询原因。删除会话不删除依法需保留的脱敏审计。

建议 API 前缀 /bi/ai：POST /conversations；POST /conversations/{id}/runs；GET /runs/{id}/events（鉴权流）；POST /runs/{id}/cancel；GET /runs/{id}；POST /runs/{id}/chart-draft；POST /runs/{id}/feedback。流通道复用现有鉴权方式，不把 token 放 URL；若原生 EventSource 不适用，采用带认证头的 fetch 流或轮询降级。

管理 API 覆盖 providers、semantic-domains、revisions、examples、evaluations 和 usage。所有资源按所有者和权限访问，不能只凭自增 ID 读取。

## 10. 评测与验收

准备固定智慧食堂数据：学校/地区、采购明细、就餐人次、学校预算、时间维度；包含零分母、空值、同名学校、跨月、无数据、过期数据、一对多预算重复与权限受限样本。脱敏或合成数据，不使用真实学生个人信息。

- R1：40 个找数/口径/解读案例，其中至少 10 个歧义或缺证据案例；人工复核正确且证据完整比例 ≥90%。
- R2：60 个固定问数案例（含 15 个澄清/拒答），另设 20 个改写问题；首轮语义及结果正确率 ≥90%，发布固定基准经限定修复后必须全部符合预期；不以一次运行替代三次重复评测。
- 安全：另设至少 30 个越权、撤权、历史读取、提示注入、缓存隔离案例，必须全部通过；任何泄露阻断发布。
- 图表：20 个草稿案例全部通过 Schema/字段校验，至少 18 个经业务复核适合表达；不自动发布。
- 输出数字能追溯至结果；无数据不编造，相关性不写成因果。
- 稳定性：模拟模型超时、限流、断流、预算耗尽、数据库超时和版本变化；既有 BI 功能继续可用。
- 性能目标：约定参考数据和网络下，找数/解释 P95≤15 秒、问数含查询 P95≤30 秒，达不到时记录分段耗时并收窄范围，不当作生产承诺。

## 11. 发布与回退

默认关闭 feature flag；先管理员与试点用户白名单，R1/R2 分别验收。模型故障显示明确提示，不影响原图表/查询入口。可单独禁用模型出域、问数或写工具；回退仅禁用 AI 入口与服务，不删除已有 BI 资源。AI 保存的图表沿用正常资源治理；出现失效语义版本，停止新查询并提示重新确认。

## 12. 尚需决策

R0 内确定：提供方与部署方式、允许出域范围、试点数据负责人、实际人员投入、用量预算。开发可先使用可重复的模拟 Provider 验证契约；真实模型和试点验证未完成时，只能标记“待模型/业务验收”。
