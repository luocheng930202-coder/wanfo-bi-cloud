# 查询治理与排查

本批控制作用于图表取数、已发布看板/大屏组件及使用同一查询服务的后台导出。权限、行列规则、发布快照和参数绑定保持原有执行顺序；校验通过后才申请查询额度。不增加数据库表或跨用户结果缓存。

## 配置

```yaml
bi:
  query-timeout-seconds: 30
  query-limits:
    max-active: 16
    per-user: 2
    per-source: 4
    max-waiting: 16
    wait-millis: 1500
    slow-millis: 3000
```

- 时间预算为一次查询作用域，包含连接准备和主查询/比较查询的 JDBC 执行；同比、环比不会重新取得完整时间预算。执行结果读取时也检查截止状态。
- 时间预算限制为 1～120 秒；建议小于浏览器 60 秒请求超时。连接池等待上限 10 秒，语句同时使用 JDBC 超时和截止时的取消信号。连接建立、网络 I/O 和物理取消能否立即响应，仍取决于数据源驱动及其连接参数；应按驱动配置有限的连接/网络超时。
- 默认 local 模式的并发限制均为**单个 BI 实例**：全局最多 16、单用户最多 2、单数据源最多 4，另允许最多 16 个请求短时排队。排队超过 1500 ms 或队列已满返回 `QUERY_BUSY`。排队时间独立于执行时间预算。
- 表数据集只占用绑定数据源的额度。SQL 数据集可能跨源，保守地一次性占用其注册的全部启用数据源额度；不会先占部分额度再等待其他数据源。
- 配置有安全边界：全局 1～64、用户 1～16、数据源 1～8、队列 0～64、排队 0～5000 ms、慢查询阈值 1～60000 ms。默认数据源连接池上限仍为 8。

## 取消与资源释放

交互查询携带随机 UUID `X-BI-Query-Key`；页面停止等待、切换查询或离开页面时，通过 `POST /bi/query/cancel` 提交 `{ "key": "对应查询标识" }`。取消请求使用正常登录认证，只匹配**服务端已验证身份**下的查询，不接受客户端提供用户身份。控制接口复用现有图表取数、数据集取数、看板消费或导出权限，不新增菜单授权。

- 同一身份不能同时复用同一个查询标识。重试使用新标识，旧取消不会取消新查询。
- 取消先到时保留最多 60 秒的短期标记，防止尚在排队/校验中的原查询随后执行；标记最多 1024 个，不记录 SQL、参数或凭据。
- Calcite 外层语句和实际数据源 JDBC 语句均接入截止/取消。包装数据源时捕获作用域，跨线程访问 JDBC 也保留相同控制；参数继续通过原 JDBC 绑定。
- 发出取消信号不提前释放并发额度。等待实际查询结束、结果集/语句/连接关闭后，再释放额度，避免旧查询尚在执行时新查询无限叠加。
- 截止调度和取消工作线程、取消任务队列均有上限。驱动不支持语句超时会失败，不静默退回无限执行。取消为尽力执行，部分驱动可能延迟响应，页面不宣称数据库已经立即停止。
- 默认 local 模式的注册表和额度在实例内；多实例应启用下文的 Redis 协调模式，以共享额度并从任意节点请求取消。后台导出执行也受预算/并发限制，但不通过页面交互查询标识取消整个导出任务。

## 慢查询与排查编号

日志关键字为 `BI slow query`，字段仅包含服务端随机 `requestId`、来源类别 `chart/dashboard/background`、执行耗时和数据源数量，不记录 SQL、绑定值、用户名、数据集名称或连接凭据。具体日志路径按部署日志配置确定。

成功响应的 `X-BI-Query-Id` 与 `queryDiagnostics.requestId` 对应；慢查询结果附带 `slow` 和 `durationMs`，图表显示缩小筛选范围建议和排查编号。失败时错误响应继续使用该服务端编号。客户端取消标识与服务端排查编号用途不同，不可互换。

控制错误保持 RuoYi 响应封装：`QUERY_BUSY`（内部 code 429）、`QUERY_CANCELLED`（499）、`QUERY_TIMEOUT`（504）。不要仅依赖 HTTP 状态判断业务是否成功。

## 验证

- 后端 391 项测试，包含超时清理、用户/数据源/全局限额、队列满与过期、原子跨源额度、用户隔离、取消先到、排队中取消、截止信号、物理 JDBC 包装及安全错误编号。
- 前端 149 项测试，覆盖取消信号只发送一次、重试标识独立、取消先于发送及网络失败处理；BI 类型检查 0 条诊断，宿主保留 268 条既有诊断，生产构建通过。
- 真实 MySQL 参数化 `SELECT SLEEP(?)` 验证执行截止、主动取消、多次查询共享预算；取消后池中活跃连接恢复为 0，连接可再次查询。
- 实际认证 HTTP 验证取消先到阻止执行、新标识重试和成功响应编号。24 个并发只读请求得到 20 个成功、4 个 `QUERY_BUSY`，无其他错误；实际慢查询编号与日志对应。浏览器验证停止请求及重新取数。


## 查询监控与多实例协调（2026-10-23）

管理员入口 `/bi-admin/query-monitor`，接口 `GET /bi/query/monitor` 与 `POST /bi/query/monitor/cancel` 均要求 `bi:resource:admin`。运行记录提供排查编号、来源、耗时、状态、数据源数量和节点随机标识，最近记录最多 200 条；不记录 SQL、参数、用户名或连接凭据。管理员停止请求通过排查编号定位，普通取消仍由服务端身份隔离。

默认 `local` 模式保留单实例行为。多实例使用同一个 Redis 数据库与命名空间，并在所有 BI 节点配置：

```yaml
bi:
  query-limits:
    coordination: redis
    namespace: wanfo-bi-prod
    max-active: 16
    per-user: 2
    per-source: 4
    max-waiting: 16
    wait-millis: 1500
spring:
  data:
    redis:
      timeout: 2s
      connect-timeout: 2s
```

- 使用宿主已有的 Lettuce 连接工厂与认证/TLS 配置；启用协调时要求命令超时不超过 2 秒，配置错误拒绝启动。各环境使用独立命名空间（1～40 个字母、数字、下划线或连字符），各节点并发/排队上限须一致。运行/排队期间发现额度配置不一致会拒绝准入，清空后可更新。
- Lua 在单个 Redis Cluster 哈希槽内原子完成全局、用户、数据源和排队额度检查；跨数据源不会分步占用。等待者每 100ms 重试，受原等待上限约束；同一身份和查询标识不能跨节点重复运行。用户标识与取消令牌仅以 SHA-256 摘要保存在共享状态。
- 每 500ms 检查跨节点取消并续租；180 秒租约只在实际查询仍运行时续期。正常结束在资源关闭后释放。任意节点均可处理普通取消和管理员停止，不要求会话亲和；取消先到标记保留 60 秒，最多 4096 项。
- Redis 不可用时拒绝新查询，已有查询请求取消，不回退本机额度；协调请求有界超时。驱动物理取消仍可能延迟。节点崩溃或租约过期后回收共享额度；网络分区持续超过租约、驱动又无法及时停止时，物理数据库连接仍可能短时重叠，部署应同时设置驱动连接/网络超时并监控数据库连接数。
- 集群监控展示共享运行、排队与最近 200 条记录。状态闲置 24 小时后过期；已完成记录不包含内部身份摘要、令牌或数据源 ID。Redis 恢复/重启的数据持久性取决于运维配置。
- 单实例内存记录与集群记录分别有界，不提供长期审计归档。

验证：真实 Redis 上两个独立 QueryGovernor 实例覆盖全局/用户/数据源限额、跨节点停止及资源释放时序、取消先到与用户隔离、重复标识、队列满与远程取消、崩溃租约回收、历史记录上限及 Redis 故障拒绝准入。CI 启动 Redis 服务自动执行该组测试；本地通过 `WANFO_TEST_REDIS_PORT` 启用，密码只通过测试进程环境提供。
