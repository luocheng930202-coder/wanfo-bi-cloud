# 数据集建模、预览与授权（2026-10-16）

本批完成受控的“数据源 → 数据库 → 表 → 字段 → 保存前预览 → 保存数据集 → 授权消费”流程，入口为 `/bi-admin/dataset`。数据源列表的“建数据集”可直接带入来源。

## 操作与权限

若依角色提供功能权限，BI 内部主体及资源授权决定具体资源的访问范围，两者同时满足才允许执行。

| 环节 | 若依功能权限 | BI 资源动作 |
|---|---|---|
| 来源选择、库表字段、保存前预览 | `bi:datasource:model` | 数据源 `model` |
| 保存表数据集 | `bi:dataset:add`，并满足上述建模权限 | 来源 `model`；非根目录还需目录 `edit` |
| 列表、定义 | `bi:dataset:list` | 数据集 `view` |
| 已保存数据集预览 | `bi:dataset:query` | 数据集 `view` + `query` |
| 删除、授权 | `bi:dataset:remove` / `bi:dataset:grant` | 数据集 `remove` / `grant` |
| 新建、删除目录 | `bi:dataset:group:add` / `bi:dataset:group:remove` | 新建子目录需父目录 `edit`；删除需目录 `remove` |

新建数据集及目录归创建者所有，记录真实操作人。用户、角色、直接部门可被授予数据集动作；若依功能权限仍独立配置。授权界面支持主体搜索、添加及撤销，资源撤权在下次请求立即生效。若依角色功能权限仍沿用登录态快照，修改后需重新登录。

数据集消费者只需要数据集权限，无需数据源管理或建模权限。已保存预览只使用服务端保存的数据库、表和字段，不接受请求体替换来源。撤销来源建模权限会阻止继续建模，不自动撤销已有数据集的消费授权；如需停止消费，应撤销数据集 `query` 或 `view`。停用数据源后不能继续查询。

## 查询边界

- 当前库表建模支持 MySQL/MariaDB 协议；范围绑定连接串指定的数据库，拒绝跨库和系统库。
- 表、字段必须通过真实 JDBC 元数据校验，标识符按驱动规则引用。最多选择 200 个字段。
- 保存前及保存后预览最多 100 行，服务端 LIMIT、最大行数及 10 秒查询超时共同约束；预览不写元数据库。
- 来源选择器不返回连接串、账号、密码。普通用户列表在字段查询前按资源权限过滤；目录仅展示有权目录及可见表数据集的祖先。
- SQL 数据集、原始 SQL、尚未接入资源策略的图表接口仍限 `bi:resource:admin`，本批未开放任意 SQL。
- 尚未实现固定行过滤、列拒绝/脱敏、目录授权继承和部门后代规则；字段选择不等于完整列权限系统。

## 升级及独立部署边界

V5 增加 `bi_dataset_table.source_catalog`，为旧数据集/目录注册无所有者的管理员管理资源；不自动给普通用户授权。旧版本为空的数据库字段在读取时仍绑定来源当前配置库。升级前备份，不改写 V1～V4 或删除迁移历史。

升级后显式重新执行 `ruoyi-bi/deploy/ruoyi-menu.sql`，新增建模及数据集菜单/按钮，再给指定若依角色分配功能权限。菜单脚本可重复执行，不自动给普通角色授权。

数据集及元数据核心继续依赖 `CurrentActorProvider`、`CapabilityProvider`、主体目录和资源授权接口；若依用户目录、登录态和响应包装留在 `adapter/ruoyi`。本批未实现独立身份服务或部署包，未来替换宿主适配实现，复用上述资源策略。
