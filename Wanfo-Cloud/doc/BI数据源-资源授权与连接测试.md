# 数据源资源授权与连接测试

实施及联调日期：2026-10-16。本批对应 S2-T09/S8-T06 的数据源部分，以及 S3-T02 的录入连接测试完善。

## 当前行为

- 新增、编辑表单均提供“测试连接”，只填写连接串、账号、密码即可先测试，无须先保存或填写资源名称。空密码可用于允许空密码的数据库。
- 结果在表单中持续显示成功/失败、数据库产品和耗时；修改连接相关字段会清除旧结果，较早请求的结果不会覆盖已修改的表单。取消/重新打开表单会清空测试状态。
- 编辑时密码留空使用服务端已保存的凭据，不回传密文或明文；连接地址、账号或驱动改变时必须重新输入密码，防止把保存的秘密发送到新目标。
- 新增和编辑保存时服务端重新测试连接；失败不新增记录，也不覆盖原配置。测试按钮本身不写入数据源元数据。
- MySQL/Doris 协议连接测试固定连接及 socket 等待上限各 5 秒，覆盖 URL 中同名超时参数；其他 JDBC 驱动尚未统一实现超时和验证 SQL 方言，不宣称已经全部支持。
- 连接错误返回可理解的提示，不返回原始驱动堆栈或凭据。新密码始终按原文测试，客户端不能提交已有 ID 通过新增接口复用保存的秘密。

## 数据源权限

两道检查同时生效：若依功能权限码 + BI 资源操作权限。资源操作为 `view/edit/test/remove/grant`，彼此独立；新建数据源的所有者拥有其全部资源操作，仍必须拥有对应功能权限码。

资源授权支持用户、角色、部门，引用 `bi_principal` 内部 ID，不直接使用 sys_* 主键；主体选择器通过若依适配器搜索当前有效的用户、角色、部门，其他身份实现可替换该契约。

主体规则为用户、所属角色及直接所属部门的显式允许取并集，无授权默认拒绝。本批未实现部门后代继承、目录继承或显式拒绝规则。资源撤销每次请求重新读取，当前会话立即生效；若依功能码、角色/部门成员变更仍沿用宿主会话快照与刷新机制。

| 操作 | 功能权限 | 资源操作 |
|---|---|---|
| 列表可见 | bi:datasource:list | view |
| 新增 | bi:datasource:add | 新资源归创建者 |
| 编辑/启停 | bi:datasource:edit | edit |
| 删除 | bi:datasource:remove | remove |
| 已保存数据源测试/批量探测 | bi:datasource:test | test；批量仅包含有 test 授权的资源 |
| 编辑表单测试 | bi:datasource:test | edit + test |
| 新建表单测试 | bi:datasource:test | 无已有资源；仅使用输入的凭据 |
| 查看/增加/撤销资源授权 | bi:datasource:grant | grant |
| 全量配置同步 | bi:datasource:sync | 另需 bi:resource:admin |

拥有 `bi:resource:admin` 的身份可管理资源；若依超级管理员的 `*:*:*` 同样满足。未向普通角色自动添加该权限。

## 数据库及菜单升级

V4 增加 `bi_resource`、`bi_resource_grant`。已有未删除数据源登记为管理员管理资源（owner_id=NULL），不根据历史 create_by 推断所有权，不给既有角色自动授权。普通角色需由管理员显式授予资源查看及相应操作。V1～V3 未改写，旧行列权限 role_id 尚未迁移或启用。

已备份开发库并由 Flyway 完成 V3→V4 升级，V0～V4 历史均成功。升级后再次执行若依菜单安装脚本，新增 `bi:datasource:grant` 按钮权限，权限菜单现在共 7 项。菜单脚本仍独立于 BI 核心迁移。

## 查询入口边界

数据源列表、修改、删除、试连、批量探测和授权接口已接入资源检查。尚未完成各自资源策略的 `/bi/**` 接口默认要求 `bi:resource:admin`，包括原始 SQL、数据集和图表接口；普通用户不能通过这些入口绕过数据源规则。后续必须接入自己的功能及资源策略后再开放，不把临时管理员限制视为行列权限已经实现。

核心授权服务只使用 BI 主体及功能权限契约；若依主体目录查询限定在 adapter/ruoyi，保留未来独立身份适配空间。
