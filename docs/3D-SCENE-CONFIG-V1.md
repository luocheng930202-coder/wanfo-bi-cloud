# 3D 场景配置协议 v1

> 状态：阶段 0 协议基线
> 适用范围：看板/大屏中的 `scene3d` 组件与屏幕模板场景槽

## 1. 结构

场景组件保存在面板 `content.scene3d` 下。当前 v1 支持内置 `map`、`building`、`chart` 三类场景，使用同一个组件渲染器。场景的数据查询绑定沿用面板的 `chartId` 与看板查询权限；场景配置不复制数据源、查询结果或凭据。

```json
{
  "componentType": "scene3d",
  "chartId": 123,
  "content": {
    "scene3d": {
      "schemaVersion": 1,
      "mode": "building",
      "cameraPreset": "orbit",
      "fallbackMode": "poster",
      "rotateEnabled": true,
      "zoomEnabled": true,
      "enabled": true
    }
  }
}
```

字段约束：

| 字段 | v1 约束 | 默认值 |
|---|---|---|
| `schemaVersion` | 整数；当前为 `1` | 旧配置缺省时按 `1` 读取 |
| `mode` | `map`、`building`、`chart` | 旧配置必须提供 |
| `cameraPreset` | `orbit`、`top`、`front` | `orbit` |
| `fallbackMode` | 当前仅 `poster` | `poster` |
| `rotateEnabled` / `zoomEnabled` | 布尔值 | `true` |
| `enabled` | 运行开关；服务端用于安全降级 | `true` |
| `fallbackReason` | 服务端生成的简短说明 | 无 |

## 2. 兼容和降级规则

1. **旧格式**：只有 `{"mode":"building"}` 的历史场景读取为 v1，并补齐 `orbit`、海报降级和交互默认值；保存时写回规范化结构。
2. **未知版本**：服务端不得尝试按 v1 执行；规范化为停用的静态预览，并附带原因。前端遇到未知版本也展示静态预览，不创建 WebGL 渲染器。
3. **v1 无效字段**：无效模式、相机或降级方式均转为停用的静态预览。API/模板输入不允许携带脚本、外部 URL、任意材质、任意组件名或任意资源路径。
4. **模板结构**：模板校验仅接受已知的场景字段。出现 v1 未识别字段时拒绝导入，给出结构不受支持；不会忽略未知字段后继续渲染。
5. **编辑恢复**：降级场景显示明确说明。用户改为受支持的模式并保存后，场景重新启用；原始未知配置不会被执行。
6. **二维保障**：场景降级只影响自身面板，不阻止同屏图表、筛选器或二维组件工作。

## 3. v1 职责边界

- `chartId` 负责既有数据绑定；`mode=chart` 使用授权查询结果的第一维度和第一度量。
- 面板布局、主题和筛选联动仍属于看板/大屏定义。
- v1 只记录相机预设和基础旋转/缩放开关；精细相机、热点编辑、地区编码映射、地图投影、模型资源、刷新策略与资源版本属于后续阶段。
- 数据绑定主要改善配置、复用和治理体验。数据更新方式与运行时刷新策略需一并设计，不能通过绑定配置直接承诺实时性。

## 4. 升级约定

增加模型资产、热点、地图投影或场景级刷新行为时，需先评审新增字段及资源权限，再升级 `schemaVersion`。旧版本读取必须保持可降级；模板升级需提供版本迁移预览，发布快照记录场景协议版本，禁止静默替换资源或绑定。
