# 3D 大屏能力改造任务清单

> 日期：2026-11-02
> 状态：待按序执行
> 设计依据：[BI 图表/看板/大屏改造计划](BI-CHART-DASHBOARD-SCREEN-REDESIGN-PLAN.md)
> 相关原则：[平台扩展实施清单](PLATFORM-EXTENSION-ROADMAP.md) §8 数据绑定与运行时刷新

## 目标与边界

在现有图表、看板和大屏能力上，构建可复用的 3D 场景展示层，用于学校区域地图、校园/食堂建筑和设备场景。3D 承载空间表达和交互，业务数据仍由现有数据集、指标、权限与查询链路提供。

- 二维驾驶舱必须可以独立制作、发布和运行；移除 3D 不得破坏二维内容。
- 图表定义保存数据查询和图表专属样式；场景定义保存模型/地图资源、相机、热点与绑定；大屏定义负责布局、主题和联动。
- 演示原型只用于验证视觉和交互，不把静态示例值作为真实业务数据。
- 先完成可绑定数据的二维校园食堂驾驶舱模板，再逐层增加可选 3D 场景。

## 执行顺序

### 阶段 0：协议与兼容基线（P0）

- [x] 盘点当前 `scene3d` 组件、场景实验页、看板定义和模板定义，形成旧配置兼容清单。
- [x] 定义并版本化场景配置 v1：模式、相机预设、基础交互、启用状态和静态预览降级；资源、图层、热点和场景刷新在后续版本扩展。
- [x] 明确配置边界：图表类型配置不包含 Three.js 场景细节；场景沿用面板授权图表绑定，不复制数据源凭据或查询结果。
- [x] 统一场景数据结果和交互协议：编辑预览和发布查看都使用面板图表查询结果；模板保留场景配置及数据槽。
- [x] 定义旧配置迁移、未知版本静态降级、无效模板结构拒绝导入及配置回滚规则。

**验收：**[3D 场景配置协议 v1](3D-SCENE-CONFIG-V1.md) 与样例 JSON 已完成；旧 `mode` 配置自动补默认值；未知场景版本和无效模式静态降级；模板含未知场景字段时拒绝导入；普通二维看板/大屏定义不受影响。

### 阶段 1：二维模板基线（P1）

- [ ] 把智慧校园食堂原型拆成标题/筛选栏、指标卡、采购与费用图表、用餐趋势、区域地图、状态列表和事件流等可复用组件。
- [ ] 为每个动态组件定义数据槽、字段类型、聚合口径、单位、过滤条件、权限要求和空/错误状态。
- [ ] 在模板编辑/实例化时支持绑定已保存图表或映射数据集字段，并显示逐槽验证结果。
- [ ] 统一模板缩略图、编辑预览和实际发布画面使用的渲染配置。
- [ ] 提供明确的演示数据标记，禁止示例数值被误识别为生产数据。

**验收：**不用 3D 模型即可制作、预览、保存、重新绑定并发布完整的 1920×1080 二维驾驶舱；绑定权限或字段不满足时无法误发布。

### 阶段 2：可视化绑定与实时刷新策略（P1）

- [ ] 建立绑定管理界面，支持数据槽选择、字段/指标映射、预览、校验、复用和变更影响查看。
- [ ] 将绑定体验定位为配置、复用和治理能力，不把它本身描述为实时能力。
- [ ] 为绑定配置数据更新方式：查询时读取、定时同步/物化或事件/CDC 更新，并显示来源更新时间与更新结果。
- [ ] 为运行时配置自动刷新周期、手动刷新、页面可见性/全屏控制、并发上限、缓存失效、超时、退避和失败状态。
- [ ] 展示数据最后成功更新时间、数据新鲜度和刷新失败原因；定义旧数据可继续显示多久。
- [ ] 记录端到端延迟：源数据变化 → 更新链路完成 → 刷新执行 → 屏幕画面更新。

**验收：**不同更新与刷新组合有可理解的配置和观测结果；重复开屏不会无界增加查询；新鲜度和端到端延迟可解释、可验收。

### 阶段 3：场景资源与 3D 基础设施（P2）

- [ ] 确定地图边界和投影数据来源、许可证、行政区编码映射及离线资源版本策略。
- [ ] 支持受控上传/引用 GLB 等模型资源，校验格式、大小、授权来源并生成预览图。
- [ ] 建立资源缓存、懒加载、加载失败重试、版本引用和安全清理机制。
- [ ] 为不支持 WebGL、资源不可达或加载超时提供静态封面/二维地图降级。
- [ ] 设计模型加载状态、场景错误和资源更新后的兼容提示。

**验收：**未授权或格式不符资源会被拒绝；场景失败不影响同屏二维图表；资源来源、版本、尺寸和加载状态可追溯。

### 阶段 4：空间地图与地区下钻（P2）

- [ ] 支持省/市/县行政层级选择、统一行政区编码和下钻路径状态。
- [ ] 地图指标绑定到地区编码与度量字段，不依赖展示名称字符串匹配。
- [ ] 支持底图主题、坐标投影、标签密度、色阶、缺失数据和选中区域样式。
- [ ] 地图选中/下钻与大屏地区筛选、普通二维地图和其他组件联动。
- [ ] 依据当前用户数据权限过滤地区及返回数据，前端场景不能扩大可见范围。

**验收：**省—市—县路径可进入/返回；切换层级不改变度量口径；无权限地区不显示数据且服务端拒绝越权查询。

### 阶段 5：建筑与设备场景（P2）

- [ ] 将校园/食堂建筑模型与设备模型拆成可复用场景资产和场景模板。
- [ ] 提供相机初始位置、缩放范围、旋转约束、热点与图层显隐配置。
- [ ] 将热点映射到学校/楼栋/设备业务编码，点击后打开指标详情或触发筛选/下钻。
- [ ] 把状态、告警、采购/用餐指标以受控标签、颜色或图表覆盖层映射到场景对象。
- [ ] 确保模型选中、鼠标提示和键盘/触控操作都能访问关键业务信息。

**验收：**替换模型后绑定仍通过稳定业务编码工作；场景热点权限与数据查询权限一致；关键状态不只依赖颜色表达。

### 阶段 6：编辑器、模板和发布闭环（P2）

- [ ] 在大屏编辑器提供场景插入、尺寸/层级调整、场景属性配置和预览入口。
- [ ] 增加独立场景配置面板：资源、相机、图层、热点、数据绑定、刷新和降级画面。
- [ ] 支持场景模板分类、预览、复制和版本化；模板实例化时重新绑定资源并复核授权。
- [ ] 发布前校验模型、数据槽、权限、刷新策略、画布尺寸和无 WebGL 降级配置。
- [ ] 发布快照记录场景配置版本、资源版本、绑定资源和模板版本，支持回滚。

**验收：**从模板创建到发布的全流程不要求手工改 JSON；编辑、预览、发布和缩略图一致；回滚恢复对应配置及资源引用。

### 阶段 7：性能、运行和验收（P3）

- [ ] 模型按需加载，评估 LOD、网格合并/实例化、贴图压缩、帧率和显存占用上限。
- [ ] 视页面可见性和全屏状态暂停/恢复动画与刷新；路由切换销毁 WebGL 资源。
- [ ] 定义典型设备档位与目标分辨率，验收普通电脑、4K 电视和低配机器降级。
- [ ] 对数据查询和场景渲染分别统计耗时、刷新时间、错误率和资源加载情况。
- [ ] 建立验收剧本：权限拒绝、空数据、过期数据、超时、断网、无 WebGL、模型缺失、快速切换地区和长时间运行。

**验收：**场景持续运行不会因资源泄漏持续增加内存；图表查询失败与模型失败互不阻断；所有异常均有可读提示和可恢复行为。

## 首轮实施建议

先做阶段 0 的协议和阶段 1 的二维模板，确认配置、字段、权限、模板预览均能闭环；再进入阶段 2 的绑定更新/刷新治理。随后按场景需求选择阶段 3–5，不以引入 3D 引擎或展示模型数量作为阶段完成标准。
