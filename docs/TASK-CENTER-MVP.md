# 数据平台统一任务中心（DP-022 MVP）

## 交付范围

统一任务中心按需读取现有运行事实，不创建第二套任务表。当前聚合数据质量运行、元数据扫描、加工预览、数仓装载、本人发起的导出、本人订阅发送历史和启用中的订阅计划。列表提供任务类型、状态、名称搜索、分页和近期成功/失败/运行数量。

后端接口：`GET /bi/tasks?type=&status=&query=&page=1&pageSize=20`。列表上限按来源读取最近记录，再合并排序；页面的统计数字仅代表已加载的近期可见记录，不是无期限的全库累计量。

## 权限与操作边界

- 页面/API 需要 `bi:task:list`。
- 每条记录继续按所属模块的功能权限和资源权限过滤；导出及订阅仅查询当前用户的记录。
- `POST /bi/tasks/{type}/{id}/cancel` 当前仅支持 `PIPELINE` 与 `EXPORT`，并委托原运行服务做权限、所有权及运行态校验。
- `POST /bi/tasks/{type}/{id}/retry` 支持数据质量、元数据扫描、加工预览及本人失败的导出任务；导出重试只复用该任务保存的请求快照，并重新经过导出创建权限、资源权限、发布版本和并发检查，不覆写原运行记录。
- 数仓装载重试仅对拥有数仓管理权限、且运行事实带有原请求快照的失败记录开放；重试复用全部非秘密参数并新建运行记录，资源权限重新检查，审计记录保存旧/新运行关系。V43 为现有新运行增加 JSON 快照列；已于 2026-10-30 随 BI 后端启动应用到本机。历史运行不含快照时继续要求从入仓页面重新配置，不猜测参数。
- 2026-10-30 V43 已随恢复后的 BI 后端启动成功应用到本机 `ry_vue`，9206 健康检查为 UP；修复后的默认 BI JAR 已恢复。失败导出/数仓装载的真实重试、权限边界和新建运行审计仍待 UI 验收。
- 质量计划暂停/恢复在质量任务模块操作；订阅启停在订阅模块操作。列表提供返回所属模块的链接。
- API 数据源刷新目前仅保留最近调度状态，没有逐次运行事实，因此暂未伪造为运行历史。

## 部署

将 `deploy/ruoyi-menu.sql` 应用到若依系统库，为有需要的角色分配“BI 资源管理 / 任务中心 / 查看统一任务中心”。BI 后端启动时会自动应用 V43；部署新后端和前端后访问 `/bi-admin/task-center`。

## 后续验收

用分别具备数据集查询、数据源建模、流水线运行、数仓管理和导出/订阅权限的账号，核对任务可见范围；运行中分别验证流水线和导出的取消；失败导出/数仓装载重试时确认创建新运行并保留原失败记录，数仓重试需检查源/目标权限与新审计记录；历史无快照运行不显示重试；其余模块确认无取消按钮；验证筛选和翻页。API 刷新逐次运行历史仍待实现。
