# 图表、看板与数据大屏整体改造计划

> 版本：0.1  
> 日期：2026-11-02  
> 状态：规划稿  
> 补充设计：[大屏主题、自由模板与 3D 组件中心设计](SCREEN-THEME-TEMPLATE-3D-COMPONENT-DESIGN.md)；主题、自由模板及 3D 资产组件相关设计以后者的细化规则为准。
> 目标原型：智慧校园食堂运行驾驶舱（二维大屏优先，3D 模型作为可选场景层）

## 1. 目标与范围

本计划把图表设计、分析看板和展示大屏作为一条完整的创作链路改造：

1. 图表负责把数据字段、指标口径和图形样式定义清楚。
2. 看板负责组织日常分析内容，适合浏览器中的筛选、联动和明细查看。
3. 大屏负责固定分辨率下的信息编排、视觉主题、展示交互和全屏运行。
4. 模板负责复用页面结构、样式和组件配置，并在创建时重新绑定数据。
5. 3D 地图、建筑或设备作为大屏中的可选场景组件，不能成为制作普通驾驶舱的前置条件。

本轮目标是让“智慧校园食堂运行驾驶舱”能够由大屏编辑器制作、保存、复制、重新绑定数据并发布。首个可交付版本不要求真实 3D 建筑模型；中央区域可使用二维行政区地图、校园分布图或普通分析图表。

## 2. 当前能力与差距

### 已有基础

- 图表可绑定数据集，支持多种图表类型、字段配置、指标聚合、地图配置和图表预览。
- 分析看板支持 12 列栅格、图表复用、筛选与联动、发布和查询。
- 大屏支持绝对坐标布局、画布尺寸与适配、组件拖动缩放、图层、分组、文本、图片、边框、容器、全屏及自动刷新。
- 模板中心已有布局选择、数据槽、从图表或数据集绑定、字段映射、绑定验证、私有模板保存和本地模板导入导出。
- 当前智慧食堂原型已展示指标卡、采购分类、费用构成、用餐趋势、区域分布、安全评分、设备状态和采购事件等目标内容。

### 主要差距

- 当前原型是独立的 Vue 页面，布局和演示数据写在页面代码中，并未由大屏定义驱动。
- 全局主题主要由纯色背景、卡片色、文字色、边框色、调色板和圆角构成，无法配置原型中的渐变、光效、局部装饰和组件级视觉差异。
- 指标卡以单一数值为主，缺少图标、单位、同比/环比、趋势迷你图、阈值状态等组合表达。
- 大屏内缺少可直接配置的标题栏、地区/时间筛选区、数据刷新提示、设备状态、预算进度和业务事件流等组件。
- 图表样式虽有类型专属配置，但缺少面向大屏的统一主题预设；同一张图表也缺少针对大屏尺寸、暗色背景和密集布局的快速风格方案。
- 模板槽主要描述图表和指标卡，模板定义还不能完整表达高级主题、专用业务组件、组件皮肤和模板版本迁移。
- 屏幕预览、模板缩略图和实际发布结果之间需要使用同一套渲染定义，避免缩略图与最终画面不一致。

## 3. 总体产品分层

| 制作区 | 主要职责 | 关键产物 | 不承担的职责 |
|---|---|---|---|
| 图表制作 | 数据维度、度量、聚合、筛选、图表类型与类型专属样式 | 可复用图表定义 | 页面级布局、整屏主题 |
| 看板制作 | 12 列栅格、分析叙事、筛选联动和明细分析 | 日常分析看板 | 大屏绝对定位、复杂舞台视觉 |
| 大屏制作 | 分辨率、自由布局、组件组合、屏幕主题、展示交互 | 可发布展示大屏 | 重新实现数据查询引擎 |
| 模板中心 | 结构复用、数据槽绑定、模板预览、版本与分类 | 可实例化模板 | 复制业务权限、数据结果或凭据 |
| 场景渲染 | 可选二维地图/三维地图/建筑/设备场景 | 场景组件配置 | 取代图表或数据绑定机制 |

图表、看板和大屏继续共用统一的查询、权限、指标格式和组件数据结果协议；各自只增加匹配其使用场景的布局和视觉能力。

## 4. 改造阶段与任务

### 阶段 0：设计协议与范围基线

- 定义图表定义、看板定义、大屏定义和模板文件的版本关系。
- 梳理组件协议：数据组件、指标组件、文本/图片、筛选控件、状态组件、场景组件。
- 为组件样式区分全局主题、组件级覆盖和图表类型专属配置，明确优先级。
- 约定模板不包含数据源密码、授权、用户数据和固定资源 ID；实例化时必须重新绑定并验证。

**验收：**形成数据结构说明、组件清单、主题变量清单和模板兼容策略；已有看板/大屏 v1 定义可继续读取。

### 阶段 1：大屏主题与布局基础

- 增加大屏主题预设：科技蓝、深色运营、明亮园区等；首个预设为“智慧校园食堂”。
- 支持背景渐变、背景图片/纹理、卡片填充与透明度、边框强调色、阴影/发光、标题层级和局部装饰。
- 支持组件级样式覆盖：边框、背景、透明度、标题、副标题、图标和内容内边距。
- 增加对齐/分布、吸附线、栅格参考、常用尺寸和边距快捷操作。
- 允许保存并复用设计尺寸、适配方式和主题；提供 1920×1080 及常见 16:9 画布预设。

**验收：**编辑器中可通过属性配置得到一致的深色科技风画布；在 1920×1080 和 16:9 电视展示下不裁切关键内容。

### 阶段 2：大屏业务组件库

优先建设可以复用在不同业务大屏中的通用组件，而不是为单一原型写死页面：

| 组件 | 必要配置 | 数据绑定方式 |
|---|---|---|
| 大屏标题栏 | 标题、副标题、品牌标识、更新时间、全屏操作 | 静态配置；更新时间由运行时提供 |
| 地区/时间筛选条 | 区域层级、日期范围、默认值、联动范围 | 绑定字段并通过统一看板筛选协议传值 |
| 组合指标卡 | 标题、数值、单位、趋势、对比期、图标、状态色 | 绑定一个或多个指标；趋势字段可选 |
| 进度/预算卡 | 当前值、目标值、比例、阈值和颜色 | 绑定当前值及目标值/预算值 |
| 运行状态列表 | 状态、设备/学校名称、更新时间、告警级别 | 绑定表格数据；可配置状态字段映射 |
| 业务事件流 | 时间、对象、类别、金额/数量、处理状态、行数 | 绑定明细查询，支持刷新与空状态 |
| 二维区域地图 | 行政区范围、位置/区域字段、指标、颜色分级、标签 | 绑定地图数据；沿用现有地图下钻和权限过滤 |
| 图表容器 | 标题、单位、说明、图例位置和卡片样式 | 包裹现有图表组件 |

通用组件可加入普通大屏；业务专属显示内容通过字段映射和样式配置表达，避免在 Vue 页面中写死食堂字段名称。

**验收：**每个组件可在编辑器插入、拖动、缩放、配置、复制、删除、保存和发布；数据组件在编辑预览与发布查看中使用相同查询结果。

### 阶段 3：图表样式与图表制作体验

- 在图表类型选择中展示不同图标、迷你示例和用途说明。
- 建立“基础配置 / 样式 / 高级”三层属性；按图表类型显示对应项，不显示无关配置。
- 为柱图增加颜色渐变、柱宽、圆角、标签、图例、坐标轴和堆叠样式。
- 为折线图增加平滑、面积渐变、点标记、阈值线和时间轴密度配置。
- 为环图/饼图增加中心指标、内外半径、标签位置、图例布局和颜色映射。
- 为仪表盘/进度图增加范围、分段阈值、中心值、单位和状态色。
- 为表格增加紧凑密度、表头、斑马纹、状态标签、固定列和异常行强调。
- 为二维地图增加色阶、缺失值、标签、地图层级和下钻状态的展示预设。
- 增加“科技大屏”风格预设，但每个图表类型继续使用自己的配置协议。

**验收：**每种图表只出现相关样式项；样式可保存到图表定义并在看板和大屏复用；切换风格不改变查询字段、聚合口径和权限。

### 阶段 4：模板定义、预览和绑定改造

- 将目前“槽位布局”扩展为版本化模板定义：布局、主题、静态组件、业务组件配置、数据槽及适配约束。
- 数据槽增加语义编码、显示名称、允许的图表类型、维度/度量要求、推荐聚合和默认展示格式。
- 支持“从已保存图表绑定”和“直接从数据集映射字段”；保留创建前预览与绑定验证。
- 模板预览使用模板本身的渲染器；不得使用另一套硬编码页面绘制缩略图。
- 导入/导出继续只传布局和样式，剔除资源 ID、权限、凭据、查询结果和租户数据。
- 增加模板协议版本、升级迁移、无效槽位报告和模板变更说明。
- 模板分类支持业务域和展示风格，例如校园餐饮/经营监控/安全监管及科技蓝/政务蓝/简洁明亮。

**验收：**原型模板可以保存到模板库；新建模板实例后，所有数据槽均需绑定并验证；删除或缺失字段会明确提示，不生成含静态演示数据的正式大屏。

### 阶段 5：制作“智慧校园食堂驾驶舱”二维模板

采用原型的视觉层次，先以二维地图和现有图表实现可交付版本：

1. **顶部：**标题、系统副标题、地区筛选、日期范围、数据更新时间、全屏入口。
2. **指标行：**采购金额、用餐人次、覆盖学校数、验收合格率；卡片可展示单位、环比和迷你趋势。
3. **左侧：**采购类别柱图、费用构成环图、近 7 日用餐折线图。
4. **中部：**二维区域地图或校园分布图；地图下钻与区域筛选保持一致。
5. **右侧：**食材安全评分、设备运行状态、用餐类型分布、最新采购/验收入库事件。
6. **页脚：**数据范围、统计时间、数据说明和运行状态。

所有数字先标明演示/真实状态。模板创建后要求为每个数据槽绑定已授权图表或数据集，不应把原型示例数值误当真实业务数据。

**验收：**1920×1080 全屏下核心指标、地图、趋势、状态和事件信息均可读；小屏预览可缩放；地区和日期筛选可联动到所有目标组件；自动刷新状态明确。

### 阶段 6：3D 场景作为可选图层

- 2D 大屏模板不依赖 Three.js、GLB 模型或 WebGL。
- 3D 场景通过独立场景组件嵌入；场景数据、相机、交互、资源地址和降级封面独立配置。
- 设备/建筑场景可以绑定业务指标，但不把 Three.js 配置塞入普通 ECharts 图表定义。
- 模型资源需有格式、大小、授权来源、加载时限、缓存、WebGL 不支持时的静态降级策略。
- 场景应支持屏幕布局中的裁剪、尺寸变化、全屏、发布权限和可访问说明。

**验收：**关闭或移除 3D 场景后，二维驾驶舱仍完整可用；模型加载失败不会阻断其他图表；场景资源不携带敏感业务数据。

### 阶段 7：发布、性能与运行治理

- 发布前检查必填槽、未授权图表、空指标、筛选目标、地图字段、刷新周期和画布溢出。
- 为大屏查询建立可配置并发、超时、缓存策略、失败重试和单组件错误提示。
- 自动刷新采用可见性/全屏状态控制，避免多个标签页重复查询。
- 模板缩略图和发布画面采用同一配置；预览环境提供“演示数据”水印。
- 发布记录保留模板版本、组件版本、绑定资源和主题版本，便于回滚。

**验收：**大屏中一个组件查询失败不会遮挡其他组件；发布版本可回滚；刷新、权限、空数据、超时、窄屏和无 WebGL 场景有明确降级行为。

## 5. 将现有原型沉淀为模板的具体流程

现有原型可以作为**视觉和信息架构样板**，不直接作为最终模板代码。建议按以下步骤制作：

1. **冻结原型参考：**记录 1920×1080 截图、组件清单、区域坐标、字体、配色和响应规则。
2. **拆解设计令牌：**提取背景、卡片、边框、强调色、警告色、字体层级、间距、光效和角标规则。
3. **拆解组件：**把原型分成标题栏、指标卡、图表卡、地图卡、状态卡、事件表和页脚；标注每个组件的输入、空状态和错误状态。
4. **定义数据槽：**例如 `purchase_total`、`meal_attendance_trend`、`school_region_distribution`、`ingredient_acceptance_rate`；槽位使用稳定语义编码，不绑定当前环境的 chartId 或 datasetId。
5. **制作模板预览：**用相同的模板定义渲染缩略图；静态预览可以显示示意图形，但所有演示值需打“示例”标识。
6. **绑定向导：**支持按槽选择已保存图表或数据集字段映射，显示字段要求和绑定验证结果。
7. **保存模板与实例化：**模板进入“校园餐饮/科技风”分类；用户创建实例时复制布局与主题、重新绑定资源并验证，模板本身保持不变。
8. **验收与版本化：**保存一个基线截图和模板定义版本；调整模板时形成新版本，已创建的大屏不被静默改写。

现有模板中心已具备模板选择、数据槽绑定、验证、私有模板保存和文件导入导出等基础，因此推荐扩展现有链路，而不是重新建设模板市场。需要重点改造的是：模板定义表达能力、组件样式协议、预览一致性和丰富的业务组件。

## 6. 建议的实施优先级

| 优先级 | 工作项 | 交付结果 |
|---|---|---|
| P0 | 组件与模板协议、主题变量、向后兼容方案 | 可评审的数据结构与验收用例 |
| P1 | 大屏主题增强、科技风预设、组合指标卡、标题/筛选栏 | 可在编辑器制作驾驶舱顶部和指标区 |
| P1 | 图表类型专属样式预设 | 采购、费用、趋势、分布等二维图表视觉统一 |
| P1 | 模板定义增强与模板预览一致化 | 原型布局可保存并从模板中心创建 |
| P2 | 状态列表、预算进度、业务事件流、二维地图联动 | 驾驶舱右侧和中部业务信息完整 |
| P2 | 校园食堂二维驾驶舱模板和真实数据绑定 | 完整的无 3D 可发布模板 |
| P3 | 三维地图/建筑/设备场景组件 | 可选的空间展示层，不影响二维模板 |
| P3 | 性能、发布回滚和多屏适配加深 | 大屏稳定运行与运维闭环 |

## 7. 总体验收标准

- 能仅使用图表、二维地图、大屏业务组件和主题配置制作完整的智慧校园食堂驾驶舱，不要求加载 3D 模型。
- 编辑器、交互预览、模板预览和发布查看使用同一份版本化定义。
- 图表定义承载数据与类型专属样式；大屏定义承载画布、主题、组件布局和筛选联动；模板定义承载可重绑定的槽位，不复制权限和数据。
- 所有真实数值来自授权数据查询；演示值明确标识，不混入正式结果。
- 普通看板和大屏各自保留适合的布局方式；共用图表和数据协议，但不强迫两种页面采用同一种视觉编辑器。
- 3D 场景可单独增加、移除或降级；移除后不影响二维驾驶舱和其他图表。
- 关键权限、过滤、超时、空值、刷新、失败与回滚路径有验收记录。

## 8. 实施边界

- 本计划不要求重写数据查询引擎、指标治理、行级权限或图表管理的底层数据模型。
- 本计划不把演示原型中的静态数值直接带入生产模板。
- 不以大量自由 CSS 输入作为主要样式方案；样式应由受校验的令牌和组件配置组成。
- 不以 3D 模型作为科技风的唯一来源；二维图表、地图、排版、状态色和动效应能独立形成完整画面。
- 模板可扩展，但第一版先覆盖智慧校园食堂和少量通用主题，不以无限模板市场为目标。
