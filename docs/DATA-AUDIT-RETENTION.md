## 能力范围

- 管理员通过「数据资产目录 → 审计」检索目录/治理操作、报表订阅投递和受控数据 API 调用记录，可按操作者（包含匹配）、动作（精确匹配）、结果及本地时间范围过滤并分页。
- 审计结果包含操作者、时间、动作、对象、数据源、结果、Trace ID 和脱敏摘要。订阅投递摘要只记录尝试次数、行数、收件人数和已清理的错误提示，不存收件人地址、报告负载、业务行或凭据。
- 目录/治理操作写入 `dp_catalog_audit`；订阅投递写入 `bi_report_subscription_audit`；受控数据 API 调用写入 `dp_data_api_call`。统一查询同时读取这三类在线记录与归档记录。API 调用审计只显示 Key 前缀，不显示 Key 或响应数据。
- 投递失败后按约 1 分钟、5 分钟间隔重试，最多三次；中间重试不发送重复站内失败通知，最终失败才通知订阅所有者。失败状态、尝试次数和消息摘要仍逐次记录。

## 保留和归档

- 管理员可将在线审计保留期设为 365～3650 天。策略默认 365 天；归档的应用保留期为长期，不由在线清理任务删除。
- 每日默认 02:25（应用时区）运行归档，可通过 `bi.audit.archive-cron` 覆盖。每次调度对每种在线审计最多归档并清理 5000 条（目录、订阅、API 调用分别处理）；积压较大时会在后续日批次继续，避免单次事务无限扩大。
- 归档写入 `dp_audit_archive`，通过 `(source_table, source_record_id)` 保证重试幂等；只有归档存在后才删除在线目录、订阅及 API 调用审计。订阅审计与订阅定义分离，因此定义删除不会级联删除投递审计。
- V42 必须先于应用新代码部署。Flyway 不会替已有迁移版本补跑；核对部署库最高版本和备份后，通过标准发布流程应用迁移。

## 权限和运行约束

- 列表、保留策略读取/更新均要求 `bi:resource:admin`，由后端能力校验。
- 查询最大页大小 100；过滤文本有长度限制；时间必须为 `YYYY-MM-DDTHH:mm:ss` 本地时间，起始时间须早于结束时间。
- 归档表采用应用追加写入路径，但数据库管理员仍可直接修改数据。若需满足法定或监管不可篡改要求，应在目标环境启用 WORM/对象锁、受控 DB 账号和外部备份，并按组织审计政策确定期限。
- 若归档失败，事务会回滚该批次，不清理源记录；告警/任务指标接入统一调度监控后需另行配置。不要仅依据界面无错误推断归档已运行。
- Prometheus/Micrometer 暴露 `bi.audit.write.failures`、`bi.audit.archive.failures`、`bi.audit.archive.duration`；元数据扫描暴露 `bi.metadata.scan.runs`（结果标签包含 SUCCEEDED/PARTIAL_SUCCESS/FAILED/REJECTED）和 `bi.metadata.scan.duration`。当前代码提供指标，生产抓取、面板、告警阈值和通知路由仍需在监控环境配置。
- SMTP/企业微信等远程发送无法由数据库事务提供端到端 exactly-once。当前在正常运行路径下抑制重试期间的重复站内失败通知；若进程恰在最终通知成功后、投递状态落库前崩溃，恢复重跑仍存在重复通知窗口。远程通道同样要用投递审计核对可能的重复投递。

## 验收步骤

1. 在备份后的开发库应用 V42，确认 `dp_audit_archive` 和单行 `global` 保留策略存在。
2. 以管理员打开目录审计，检查目录操作与订阅投递混合展示，逐项验证操作者、动作、结果、时间过滤及分页总数。
3. 将在线保留期暂设为最小 365 天；在隔离验收库把一条合成审计记录的时间置于截止日前，调用归档调度或等待计划任务，确认在线行删除且归档记录可检索。避免在生产库手工改写时间。
4. 重复运行归档，确认归档唯一键不产生重复且审计结果仍只出现一份；确认更新在线期限后旧记录仍可在归档查询。
5. 使用隔离的失败通知通道制造订阅失败，核实两次重试后仍只记录审计而不发站内提醒，第三次终止后发出一次站内提醒；确认订阅所有者之外的账号不能查看或修改策略。
6. 留存迁移版本、归档前后计数、权限正反例、调度日志和失败通知记录作为 DP-030 验收证据。
