# 零售指挥大屏 — 搭建手册

## 0. 前置

- MySQL：`mysql-dev:3410`，库 **`bi_phase_a_test`**（与 BI 数据源 **id=58** 一致；若你换了 JDBC，请把脚本改到对应库）。
- 服务：网关 8080、BI 9206、前端 80、登录 `admin` / `admin123`。
- 菜单：已执行 `ruoyi-menu.sql` 并给角色 BI 树。

### 装载演示数据

```powershell
powershell -ExecutionPolicy Bypass -File D:\datacenter\Wanfo-Cloud\ruoyi-modules\ruoyi-bi\deploy\seed-retail-screen.ps1
```

预期：`dim_store` 6 行、`dim_product` 8 行、`fact_order` 约 3200 行。

### 一键 API 建数据集 + 运营监测模板大屏草稿（数据源 58）

```powershell
pwsh -ExecutionPolicy Bypass -File D:\datacenter\Wanfo-Cloud\ruoyi-modules\ruoyi-bi\deploy\bootstrap-retail-screen-api.ps1
```

会创建 `ds_store` / `ds_product` / `ds_order`（含与 `dim_store` 的单表关联）/ `ds_retail_wide`（视图宽表 + 计算字段 `unit_price`）等；默认 **`-Profile full`** 会保存 **10 张图表**（柱/线/饼/漏斗/地图/透视/仪表/明细/KPI×2）并升级同名大屏草稿（15 个组件：容器、装饰、筛选×4、品类→明细联动、30s 刷新）。仅要市场模板四槽位时用 `-Profile template`。加 `-ForceNewDashboard` 可另建一份大屏。请用 **pwsh** 执行（避免中文编码问题）。

## 1. 数据源与数据集

1. **BI 资源管理 → 数据源**：确认 id=58（或新建指向 `bi_phase_a_test` 的 MySQL）试连成功。
2. **数据集**（表类型）：选表后会带出 **物理字段名 / 类型 / 库表注释**；**显示名称**默认取注释（可改），保存后写入 `show_name`。图表、看板、大屏展示用显示名称，查询仍用物理字段名。已建数据集可在 **建模 → 显示名称** 修改，或批量同步：

```powershell
# 先给演示表补 COMMENT，再把 ry_vue 里已有数据集的 show_name 按 information_schema 刷新（默认数据源 58）
pwsh -ExecutionPolicy Bypass -File D:\datacenter\Wanfo-Cloud\ruoyi-modules\ruoyi-bi\deploy\refresh-dataset-show-names.ps1
pwsh -File ...\refresh-dataset-show-names.ps1 -DryRun          # 仅预览将变更的字段
pwsh -File ...\refresh-dataset-show-names.ps1 -AllDatasources  # 所有 MySQL 表数据集
pwsh -File ...\refresh-dataset-show-names.ps1 -SkipRetailComments  # 已手工 COMMENT 时跳过
```

演示库列注释：`deploy/demo-retail-column-comments.sql`（全量种子 `demo-retail-screen.sql` 已内置 COMMENT）。

| 数据集名 | 物理表 | 主要字段 |
|----------|--------|----------|
| `ds_store` | `dim_store` | store_id, store_name, province, city, open_date |
| `ds_product` | `dim_product` | product_id, product_name, category, list_price |
| `ds_order` | `fact_order` | order_id, order_date, store_id, product_id, channel, qty, amount |
| `ds_target` | `dim_target` | month_key, province, target_amount |
| `ds_ops_note` | `ops_retail_note` | note_date, province, channel, content |

3. **关联建模**（在 `ds_order` 上打开建模对话框）：
   - `fact_order.store_id` = `dim_store.store_id`（LEFT）
   - `fact_order.product_id` = `dim_product.product_id`（LEFT）
   - 保存后预览应出现：`province`, `city`, `store_name`, `category`, `product_name` 等。

4. **计算字段**（宽表/订单数据集，按界面支持的公式）：
   - 名称 `unit_price`，表达式语义：`amount / qty`（除零按工具默认处理）。

授权：admin 默认可见；若用副账号，给数据集 **查看/查询/看板消费**。

## 2. 图表（建议先独立保存）

| 图表名 | 类型 | 维度/度量要点 |
|--------|------|----------------|
| 零售-区域柱图 | bar | 维 `province`，度 `SUM(amount)`；高级下钻：`province` → `city` → `store_name` |
| 零售-日趋势 | line | 维 `order_date`，度 `SUM(amount)` |
| 零售-渠道漏斗 | funnel | 维 `channel`，度 `SUM(amount)` |
| 零售-品类饼图 | pie | 维 `category`，度 `SUM(amount)` |
| 零售-省级地图 | map | 维 `province`，度 `SUM(amount)`，范围「中国省级」 |
| 零售-品类区域透视 | pivot | 行 `category`，列 `province`，度 `SUM(amount)` |
| 零售-订单明细 | table | 维 `order_date`,`store_name`,`channel`…，度按需 |
| 零售-达成率 | gauge | 需自行用聚合或子集验证；或 KPI 显示 `SUM(amount)` |

下钻图 **不要** 在看板里配成「联动来源」。

## 3. 数据大屏（模板起步）

1. **看板管理 → 新建数据大屏 → 模板市场 → 运营监测大屏**。
2. 向导选择数据集 **`ds_order`（建模后宽表）** 或你命名的宽表数据集，字段映射参考：

| 模板槽位 | 建议绑定 |
|----------|----------|
| metric-a（KPI） | `SUM(amount)` 或 `COUNT(order_id)` |
| metric-b（KPI） | `SUM(qty)` 或第二指标 |
| analysis-a（柱图） | 维 `province`，度 `SUM(amount)`，并同步图表高级下钻三层 |
| analysis-b（明细） | 明细表字段：日期、门店、渠道、金额 |

3. 创建后进设计器 **增补组件**（注意总数 ≤20）：
   - 地图、漏斗、透视、折线、标题 text、LOGO image、container 包住左侧 KPI。
   - **场景**：1920×1080，适配「等比」，**自动刷新 30** 秒。
4. **筛选与联动**（整板）：
   - 控件：`city`(text)、`channel`(enum)、`amount`(number 区间)、`order_date`(date 区间)。
   - 联动：用 **非下钻** 的柱图或饼图 → 明细表（不要用下钻区域柱图作来源）。
5. **草稿交互预览** → 无报错后 **发布** → 列表 **查看** / 全屏。

## 7. 常见问题

| 现象 | 处理 |
|------|------|
| 地图无数据 | `province` 须为 `浙江省`、`北京市` 等省级全称 |
| 下钻无数据 | 检查维值中文是否乱码；可重装 `seed-retail-screen.ps1` |
| 联动不生效 | 来源须为第一维度；下钻图不能作来源 |
| 模板槽位红字 | 向导 remap 字段名，或手改组件图表配置 |
