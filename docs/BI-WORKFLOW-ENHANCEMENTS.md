# BI 工作流优化（2026-10-25）

本批按五项建议顺序实施。多数据源实库完整验收仍单独保留，不纳入本批完成范围。

## 1. 图表字段配置与即时校验

编辑图表的数据面板新增实时检查区，说明缺少的数据集/字段、过期或无权使用的字段、重复维度/结果名、聚合方式不匹配、未完成筛选以及透视行列设置。错误配置阻止提交查询和保存；非负值、混合量纲等需要读取实际数据才能判断的问题作为提醒，仍由服务端继续校验。

保留现有图表合法配置，包括散点原始值查询。自动查询不会在每次不完整编辑时弹出重复警告；手动更新仍给出明确原因。

## 2. 资源引用关系与变更影响

数据源、数据集列表增加“引用关系”；图表、看板的更多菜单提供同一入口。显示数据源 → 数据集 → 图表 → 看板/大屏的显式绑定关系，以及当前可见下游资源。

所有节点都经过功能权限及资源查看权限过滤；普通发布查看者不读取草稿名称或草稿引用。节点不包含 SQL、字段条件、连接信息或凭据。草稿与发布快照的绑定分开显示。删除仍使用现有服务端引用保护；数据集被引用时不再通过错误消息返回未授权图表名称。

当前最多展示 200 个节点，候选元数据最多 2001 条、绑定最多 6001 条；达到限制提示结果不完整。SQL 数据集的任意跨源 SQL 尚无完整解析血缘，不能据此断言某资源完全没有其他依赖。当前入口是只读影响分析，不提供自动改名传播或自动解除引用。

## 3. 历史版本、配置比较和恢复

图表、看板/大屏更多菜单增加“历史版本”。保存时记录版本、操作人、操作及配置，最多保留最近 50 个版本；已有资源在首次修改时补存当前版本，不伪造此前历史。

支持历史配置预览、与当前保存配置的结构差异比较，以及恢复为新草稿。比较最多显示 200 处变化，大段文本摘要显示。恢复必须提供当前版本号，走现有保存校验，字段、资源权限或版本冲突均不能绕过。读取历史配置也重新验证当前可用字段与资源权限。

恢复不自动发布、不改变当前发布修订号、不回滚数据库业务数据，也不恢复已撤销的授权。记录的是图表/看板草稿配置及发布操作；历史业务数据与历史发布时冻结的整套查询结果并未存档。

Flyway V22 新建 `bi_resource_history`。不覆盖当前资源定义，不修改现有发布快照。删除资源后历史接口仍拒绝读取该资源。

## 4. API 分页、自动刷新与文件导入

- API 支持显式页码分页：页码参数、页大小参数、起始页 0/1、每页 1～1000 行、最多 100 页、总行数 JSON 路径。尝试识别常见 total/totalCount；响应需遵循配置的页大小协议。
- 累计最多 5 MB、20000 行，应用执行预算 30 秒，网络操作继续使用有限连接/读取超时。重复页、总数变化、空页提前结束或达到上限仍未读完整时，拒绝替换原快照。无法保证上游分页期间数据完全静止，生产接口应提供稳定排序或上游快照。
- API 可选择每 5～1440 分钟自动刷新，0 为关闭，默认关闭。默认每分钟检查到期任务；两个后台工作线程和有界任务队列，数据库租约及快照版本检查协调多个 BI 节点。任务只更新明确配置的快照，不采用作者身份查询或对外返回数据。
- 停用/删除的数据源不开始新的刷新；失败保留旧数据并提供无敏感信息的状态。服务端 `bi.external-source.scheduling-enabled=false` 可关闭调度；`bi.external-source.poll-ms` 默认 60000。
- 文件可先预览前 10 行及字段类型，再设置文本、数值、布尔、日期、日期时间；保存时检查全部数据。
- 已有文件源支持覆盖或按行追加。追加保持字段和既有类型兼容，累计仍受行数/容量限制；不自动去重，重复上传会产生重复记录。结构变化应创建新数据源。

Flyway V23 新建 `bi_source_refresh`，不默认开启任何现有数据源的定时任务。仍沿用精确 API 来源允许列表、请求头加密和禁止重定向策略。当前不支持游标/令牌分页、POST、OAuth 自动续期、嵌套 JSON 展开或自动结构迁移。

## 5. 权限隔离的结果缓存

表数据集列表增加“缓存设置”，默认关闭；可配置 5～300 秒。设置要求数据源建模资格、资源授权和所属目录编辑权限。

每次请求先检查当前访问权限、行列策略和字段有效性，再查缓存。键包含已验证用户、组织/角色、当前编译 SQL/参数、字段类型、查询配置、数据源配置摘要及文件/API 快照版本，不能由客户端身份参数决定共享范围。

缓存仅用于当前节点、当前用户的交互查询。容量最多 200 条、序列化载荷 8 MB，单条最多 512 KB；响应做深拷贝，保留高精度数字，不缓存失败、SQL 调试内容及旧排查编号。后台导出不使用该缓存。

文件/API 更新后因快照版本变化立即失效；图表手动“更新数据”携带 `X-BI-Cache-Bypass: true` 直接取数。数据集缓存设置改变会清理旧缓存；管理员可在查询监控查看当前节点命中/占用并清理。

外部数据库自身的数据/权限变更不能自动通知当前缓存，启用后可能在 TTL 内看到旧数据；需要立即更新时手动刷新或清缓存。当前未加入跨节点共享结果缓存、重复 SQL 请求合并或预聚合引擎。

## 验证与发布

本批新增前端配置和版本差异测试，以及后端资源权限、历史恢复/持久化、分页、定时租约、文件追加和缓存隔离测试。实际服务验证迁移、显式引用链、历史恢复/版本冲突、发布版本保持、文件预览/追加、API 分页/自动刷新/失败保留、缓存命中/绕过/快照失效及原地图查询。验收使用单独记录的模拟资源，结束后清理。

发布需同步前后端并执行 V22/V23。正式上线前备份元数据库；不以删除历史或调度表的方式回滚。旧版服务回退后新增表可保留，已保存新分页配置不应交给旧版服务刷新。
