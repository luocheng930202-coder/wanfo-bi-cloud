## 布局与取数

参照 `SmartCanteenScreen.vue` 的深蓝科技风、顶部四指标、左侧三分析区、中央三维建筑、底部区域/设备和右侧安全/餐次/验收结构。

数据来自本地 MySQL 数据源 58 的独立 `demo_canteen_*_v1` 演示表；数据集和图表名称均带“智慧食堂演示”前缀。所有数值均为虚构样本，页面已注明，不代表真实学校情况；刷新重新查询固定样本，不自动产生新业务记录。

这些专用演示数据集启用 300 秒用户查询缓存，减少重复打开静态样本时的取数开销。缓存仍遵循现有用户权限范围；卡片显示的是查询成功时间，可能命中缓存，不代表源表刚刚更新。没有修改其他业务数据集的缓存策略。

样本口径：

- 采购总额 286.4 万元，五个食材品类相加等于采购总额。
- 学生就餐 326,000 人次，展示为 32.6 万人次；示例周和餐次分布分别汇总到该值。
- 区域学校数量 24 所，江苏五市学校数相加为 24；地图使用平台现有行政区边界能力。
- 验收合格率 99.2%，安全评分 98.6，为独立示例指标。
- 费用构成合计 462 万元，包括采购、人员、能源及其他费用，避免与单独采购口径混淆。
- 设备温度、采购入库记录为虚构示例，不与总采购额作逐笔对账。

中央建筑复用原型现有的程序化三维场景，支持旋转、缩放；不是实际校园测绘模型。设备不支持 WebGL 时沿用静态降级与重试能力。

## 为本次制作补齐的编辑能力

- 组件字号、文字颜色和透明背景，均可在右侧“样式”修改，并随草稿、发布和模板文件保存；字号 10–96，颜色仅允许六位十六进制值。
- 隐藏标题的组件在编辑时保留浮动拖动条，在查看时不占额外标题高度。
- 看板内的图表使用自适应嵌入模式，不再使用单图编辑页固定高度和附带明细表；保留图表交互、地图复位和单图编辑页的明细能力。
- 深色加载遮罩与表头跟随主题，保留表格专用表头配色。
- 三维场景在相机或内容变化时重绘，避免静止建筑持续重复绘制；继续保留不可见暂停、资源释放和失败降级。

## 重新建立演示

1. 将后端 `ruoyi-modules/ruoyi-bi/deploy/demo-school-canteen.sql` 执行到用于演示的 MySQL 数据库。该脚本仅创建专用演示表并插入缺失行。
2. 设置本地环境变量 `WANFO_DEMO_USERNAME`、`WANFO_DEMO_PASSWORD`；也可使用已有、被 Git 忽略的后端 `.local-login.json`。不要把账号密码写入本脚本或提交。
3. 运行后端 `ruoyi-modules/ruoyi-bi/deploy/bootstrap-school-canteen.mjs`。可用 `WANFO_DEMO_DATASOURCE_ID` 指定演示数据源，默认 58；`WANFO_DEMO_API` 默认本地网关 8080。
4. 脚本更新同名专用演示图表和演示草稿，验证 12 张图表取数；不会自动发布。若手工修改过该演示，请先另存副本，再重跑脚本。

不要将该脚本指向生产数据源，也不要用它覆盖真实看板。本次仅在本地发布演示以便查看；代码按要求不提交、不推送。
