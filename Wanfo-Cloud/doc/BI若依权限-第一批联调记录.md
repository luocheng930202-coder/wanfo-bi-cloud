## 联调修正

1. 依据实际网关依赖 `spring-cloud-gateway-server-webflux-5.0.2` 内的配置元数据，将本地路由配置改为 `spring.cloud.gateway.server.webflux`。
2. BI 控制器本身使用 `/bi/**`，网关 BI 路由保留该前缀，移除错误的 StripPrefix。
3. 补充认证与验证码入口白名单，BI 和系统接口仍经过网关身份检查。
4. 同步 `seed_nacos.py` 的网关配置模板，并解析核对生成模板与本地配置一致；未运行整个配置初始化脚本或重写 Nacos 数据库。
5. `spring.config.additional-location` 指定目录时只会按应用默认配置名寻找文件，不能自动加载 `ruoyi-gateway-dev.yml`。联调启动网关时显式加入该文件，否则没有业务路由。
6. 数据源只读状态开关改为禁用显示，避免隐藏整个控件后用户看不到状态。

## 当前访问与重启

- 前端：`http://127.0.0.1/bi-admin/datasource`。
- 网关：8080；认证：9200；系统：9201；BI：9206。前端 `/dev-api/bi` 直连 BI，其余 `/dev-api` 走网关；另外验证网关 `/bi/**` 也可正常转发。
- 本次后台进程 PID、日志在工作区 `.local/bi-integration/`。进程使用限制堆大小的 JVM 参数；本次网关禁用 Sentinel 以降低本地资源占用，未验证生产限流。
- 本次依赖本地配置文件，Nacos 配置读取为空的提示不表示本地配置加载失败。服务发现已通过真实 auth→system 调用验证。

网关重启须显式包含两个配置来源：

```powershell
java -Xms32m -Xmx160m -XX:MaxMetaspaceSize=144m -XX:MaxDirectMemorySize=32m -XX:ActiveProcessorCount=2 `
  -jar D:/datacenter/Wanfo-Cloud/ruoyi-gateway/target/ruoyi-gateway.jar `
  --spring.config.additional-location=file:D:/datacenter/ruoyi-nacos-config/,file:D:/datacenter/ruoyi-nacos-config/ruoyi-gateway-dev.yml `
  --spring.cloud.nacos.discovery.ip=127.0.0.1 `
  --spring.cloud.sentinel.enabled=false
```

重启前核对端口及原进程，不要重复启动。其他服务至少加载公共 `application-dev.yml`；需要各服务专用本地文件时同样显式添加。部署到 Nacos 配置分发环境时，以该环境的实际配置和资源配额重新验证。
