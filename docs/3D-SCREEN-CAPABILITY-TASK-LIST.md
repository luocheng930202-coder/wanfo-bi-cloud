## 目标与边界

在现有图表、看板和大屏能力上，构建可复用的 3D 场景展示层，用于学校区域地图、校园/食堂建筑和设备场景。3D 承载空间表达和交互，业务数据仍由现有数据集、指标、权限与查询链路提供。

- 二维驾驶舱必须可以独立制作、发布和运行；移除 3D 不得破坏二维内容。
- 图表定义保存数据查询和图表专属样式；场景定义保存模型/地图资源、相机、热点与绑定；大屏定义负责布局、主题和联动。
- 演示原型只用于验证视觉和交互，不把静态示例值作为真实业务数据。
- 先完成可绑定数据的二维校园食堂驾驶舱模板，再逐层增加可选 3D 场景。

## 执行顺序

**已确认的模板流程：**中心只设“模板市场 / 我的模板”，团队共享通过授权管理。先预览风格，再选择完整布局或仅用视觉风格。当前已接通两种入口、常用图表的独立演示数据预览和基础外观空白创建；完整布局仍沿用逐槽绑定向导。演示值仅用于预览，不写入草稿；完整原型风格、主题/模板不可变版本和未绑定数据组件草稿按补充设计继续推进。

**当前优先级修正：**现有基础外观与普通图表预览，同独立智慧食堂原型存在明显组件及样式差距。下一步优先按补充设计 §7.5 的 VIS-01～08 提取主题、标题、科技面板、组合指标卡、图表风格和业务展示组件，再用编辑器重建原型布局。未完成同分辨率、同演示数据的逐区视觉对照前，不认定“原型已模板化”或“风格已还原”。

**当前进度（2026-11-02）：**阶段 0 已完成；阶段 1 已补充校园食堂模板、槽位口径/类型校验、单位、统一筛选默认值和真实整屏预览，大屏/栅格模板预览均已复用实际画布；阶段 2 已开始接入创建时刷新策略、查询成功时间及失败退避。业务字段语义、跨数据集筛选、发布和缩放效果仍待实际验收，源数据新鲜度链路尚未闭环。

- [ ] 为每个动态组件定义数据槽、字段类型、聚合口径、单位、过滤条件、权限要求和空/错误状态。

  - 绑定验证已增加逐槽查询结果：无数据、度量全空、真实零值和可能达到行数上限分别提示；缺失组件响应不得判定为通过。确认页保留查询结果摘要，修改绑定后清除旧摘要；查询期间暂停绑定修改。登录失效、权限不足、超时和网络失败提供不同提示。空数据可创建草稿，不代表已完成发布或业务口径验收。
  - 已在模板向导增加可选的日期、学校、地区统一筛选，逐组件明确映射字段，映射不完整或类型不匹配时阻止创建；创建时映射到新实例组件标识，并交由已有后端协议验证和执行。日期筛选目前要求 DATE 字段，时间戳须先在数据集中转换；学校/地区编码须同类型、同编码体系，后者仍需业务确认。默认不限定筛选值，已保存图表自身的过滤条件及服务端数据权限仍然生效。真实跨数据集筛选效果与发布运行尚待浏览器验收。
  - 统一筛选支持默认日期范围与学校/地区编码，校验日期合法性、起止顺序、编码类型和长度；逐槽验证、整屏预览与保存使用同一组默认条件。修改条件后清除旧验证结果。
- [x] 复用现有模板创建向导，支持绑定已保存图表或映射数据集字段，并在创建前逐槽验证。
- [ ] 统一模板缩略图、编辑预览和实际发布画面使用的渲染配置；目前缩略图是带水印的布局示意。

**验收：**不用 3D 模型即可制作、预览、保存、重新绑定并发布完整的 1920×1080 二维驾驶舱；绑定权限或字段不满足时无法误发布。

### 阶段 2：可视化绑定与实时刷新策略（P1）

- [ ] 建立绑定管理界面，支持数据槽选择、字段/指标映射、预览、校验、复用和变更影响查看。
- [ ] 将绑定体验定位为配置、复用和治理能力，不把它本身描述为实时能力。
- [ ] 为绑定配置数据更新方式：查询时读取、定时同步/物化或事件/CDC 更新，并显示来源更新时间与更新结果。
- [ ] 为运行时配置自动刷新周期、手动刷新、页面可见性/全屏控制、并发上限、缓存失效、超时、退避和失败状态。
  - 模板创建向导已提供手动或 10/30/60/300/900 秒自动刷新选项，写入 scene.refreshSeconds；复用现有发布查看页的页面隐藏暂停和串行周期调度。本向导不启动定时查询；完整的新鲜度、退避及缓存失效验收仍待后续完成。
  - 自动刷新连续失败时已增加指数退避；以 10 秒周期为例，失败后依次等待 20/40/80 秒，最大为 300 秒或用户原周期中的较大者，成功后恢复原周期。发布查看和草稿预览都向调度器反馈失败，状态栏显示连续失败次数和重试等待。隐藏、销毁、前台查询占用及在途取消仍沿用原保护。模拟时钟测试已覆盖失败退避、恢复、无并发堆积和停止后的清理；真实断网/超时运行仍待验收。
- [ ] 展示数据最后成功更新时间、数据新鲜度和刷新失败原因；定义旧数据可继续显示多久。
  - 发布查看页与模板真实预览已显示最近查询成功时间，并明确其可能包含缓存、不等于源数据更新时间；失败、取消、筛选变化和配置版本变化时不会沿用失效的查询时间。源数据更新时间、允许滞后时长和端到端延迟仍待后端链路提供可信元数据后实现。
- [ ] 记录端到端延迟：源数据变化 → 更新链路完成 → 刷新执行 → 屏幕画面更新。

**验收：**不同更新与刷新组合有可理解的配置和观测结果；重复开屏不会无界增加查询；新鲜度和端到端延迟可解释、可验收。

### 阶段 4：空间地图与地区下钻（P2）

**数据表达前置修正：**已移除程序化地图中的固定分区和固定学校点位；未绑定行政区地图图表时显示待配置。3D 柱图不再自动生成示例业务值；未绑定、查询中、缺少度量、无数据和无有效数值分别提示，显示真实零值、保留负值方向，并提示无效值和前 5 条展示限制。

**行政区地图首轮实现：**3D 场景已复用绑定地图图表返回的 MapContext、地区编码及现有本地边界接口，支持 Polygon/MultiPolygon 与洞环，并保留辅助边界线；只对当前授权结果中的编码赋值，未匹配/无效/重复编码分别提示，不猜测名称或前端重聚合。几何只采用经纬度自适应平面展示，不作为测绘投影。无 WebGL 时可显示同一边界的二维 SVG；边界失败可重试，切换范围/退出时取消旧请求并拒绝过期结果。

**交互首轮实现：**发布查看与草稿预览支持单击选择、双击或地区列表按钮下钻，已有联动配置时可筛选地区，返回路径沿用原看板面包屑。仅匹配到授权结果且服务端标记有可用子级的地区发起下钻，叶子/缺数据地区不发起；仍由服务端校验路径与权限。编辑画布与模板静态预览禁用查询交互。真实省市县 GPU 展示、跨角色权限及连续切换仍待页面验收；学校坐标点位、主题配置与可选投影尚未实现，因此以下验收项仍暂不勾选。

- [ ] 支持省/市/县行政层级选择、统一行政区编码和下钻路径状态。
- [ ] 地图指标绑定到地区编码与度量字段，不依赖展示名称字符串匹配。
- [ ] 支持底图主题、坐标投影、标签密度、色阶、缺失数据和选中区域样式。
- [ ] 地图选中/下钻与大屏地区筛选、普通二维地图和其他组件联动。
- [ ] 依据当前用户数据权限过滤地区及返回数据，前端场景不能扩大可见范围。

**验收：**省—市—县路径可进入/返回；切换层级不改变度量口径；无权限地区不显示数据且服务端拒绝越权查询。

### 阶段 7：性能、运行和验收（P3）

- [ ] 模型按需加载，评估 LOD、网格合并/实例化、贴图压缩、帧率和显存占用上限。
- [ ] 视页面可见性和全屏状态暂停/恢复动画与刷新；路由切换销毁 WebGL 资源。
  - 现有 3D 组件已按页面可见性、路由激活状态和可视区交集暂停/恢复动画；失败、重试及销毁时清理帧、尺寸监听、控制器和旧 canvas。共享网格、线条、材质、文字贴图及阴影目标统一释放，避免误销毁 Three.js 跨场景共享的 Sprite 几何体。资源释放单元测试通过，真实 GPU 上下文恢复和长时间运行仍待验收。
- [ ] 定义典型设备档位与目标分辨率，验收普通电脑、4K 电视和低配机器降级。
- [ ] 对数据查询和场景渲染分别统计耗时、刷新时间、错误率和资源加载情况。
- [ ] 建立验收剧本：权限拒绝、空数据、过期数据、超时、断网、无 WebGL、模型缺失、快速切换地区和长时间运行。

**验收：**场景持续运行不会因资源泄漏持续增加内存；图表查询失败与模型失败互不阻断；所有异常均有可读提示和可恢复行为。
