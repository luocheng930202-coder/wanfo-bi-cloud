## 1. 文档目的和使用规则

本清单把“建设一个真正的数据平台”拆成可实现、可分期、可验收的功能点。它同时作为产品需求、开发任务拆分、权限设计、测试范围和上线准入的追踪基线。

**本清单不代表所有列出的功能已经开发。**状态以 2026-10-27 仓库文档和代码结构为快照；“已有基础”只说明存在可复用能力，不代表已达到本文验收标准或完成生产环境验收。

### 1.1 状态定义

| 状态 | 说明 |
|---|---|
| **已有基础** | 当前代码已有对应功能或组件，可复用；仍需按本清单补验收、统一入口/模型或运行治理 |
| **需完善** | 有局部实现，但缺少完整生命周期、边界条件、平台联动或审计 |
| **待新增** | 当前没有满足目标的完整能力，需要设计和开发 |
| **待环境验收** | 功能已有代码或本地基础验证，但真实外部系统、生产配置、权限角色或负载尚未验收 |
| **暂缓** | 列入长期能力，但不进入当前阶段，需先有业务/容量触发条件 |

### 1.2 优先级定义

- **P0（平台闭环）**：缺少时无法安全、可信地形成平台核心闭环；应优先交付。
- **P1（平台运营）**：让平台可日常治理和服务化；P0 稳定后交付。
- **P2（规模扩展）**：面向更高数据量、实时性、生态或多租户复杂度；根据业务触发。

### 1.3 通用验收要求

每项通过验收时，至少保存：需求 ID、提交/PR、数据库迁移版本、测试结果、权限场景、失败场景、UI/API 验收记录和遗留限制。功能、后端权限、数据库迁移、可观测性、用户操作说明任何一项缺失，都不能只凭“页面能打开”标记完成。

## 2. 当前能力基线

结合本仓库 `docs/PLATFORM-EXTENSION-ROADMAP.md`、`docs/DATASOURCE-CONNECTORS.md` 和 BI 代码目录：

- **BI 核心已有基础**：数据源、数据集/字段、指标、图表、看板/大屏、导出、订阅、查询治理、行列数据权限、资源历史/影响分析、数据集关系建模、清洗步骤与只读回放。
- **数据源已有基础**：MySQL/Doris/StarRocks、PostgreSQL、SQL Server、Oracle、ClickHouse；JSON API、CSV、Excel 快照。PostgreSQL/ClickHouse/SQL Server/Oracle 曾在本地容器做过连接/预览冒烟；细节和未覆盖边界见 `docs/DATASOURCE-CONNECTORS.md`。本地实连不等同生产 TLS、复杂查询和容量验收。
- **API 与文件已有基础**：OAuth 客户端凭据及授权码 + PKCE、分页、数组展开、快照更新；文件预览、字段类型、追加/覆盖、异常行报告。授权提供方、真实 API、文件结构变更迁移仍需按具体场景验收。
- **治理已有局部基础**：质量规则和全量扫描、资源依赖影响分析、历史版本等 BI 范围能力；尚未形成覆盖数据库源表、数据集、指标、报表、API 的统一资产目录与端到端治理工作台。
- **需要特别跟踪**：文件字段变更后的依赖自动迁移/回滚未完成；DAG 级可视化流程、可持续调度的质量运营、统一任务中心、统一指标口径、数据服务目录/API Key 的完整产品闭环仍需建设或确认。
- **运行验收边界**：订阅的 SMTP/企业微信真实投递、多实例任务治理、生产追踪栈与 TLS、容量/SLA 等不能只用本地自动化测试代替。
- **当前工作区注意项**：上一轮本地启动发现 BI 的 OAuth 服务使用了未被 Spring Boot 自动配置的 Jackson 类型，已在工作区改为 Boot 4 所用类型并完成 BI 构建/启动验证；该源码修复尚未提交，应在阶段 0 完成评审、回归和提交。

参考工程中的 `zl-governance`、`zl-data-api` 和治理/数据服务页面可作为领域模型与交互参考；其认证、ORM、模块代码不直接视为 Wanfo 的实现，也不应跳过适配评审进行复制。

## 3. 用户角色和核心权限矩阵

权限分为**功能权限**与**数据/资源权限**两层。菜单权限不能替代服务端对资源、数据源、行列范围和租户的校验。

| 角色 | 主要工作 | 关键权限边界 |
|---|---|---|
| 平台管理员 | 配置全局策略、连接器、角色、审计和告警 | 默认不因此绕过敏感数据访问审计；高风险操作需单独权限 |
| 数据源管理员 | 登记连接、测试连接、授权用户/角色、维护连接状态 | 只能管理被分配的数据源；密码与 Token 不可回显 |
| 数据工程师 | 建模、清洗、流程编排、发布与运行 | 只能读写授权源和目标；流程执行使用最小权限凭据 |
| 数据管理员/质量负责人 | 维护资产说明、分类分级、质量规则、责任人和问题闭环 | 规则定义与查看违规明细可拆分授权 |
| 分析师 | 搜索和申请数据、创建数据集/图表/看板 | 只能查询已授权资产，沿用行列规则 |
| 数据服务管理员 | 发布 API、管理服务账号、配额与消费者 | 不能通过 API 绕过源资源权限；密钥只在创建时展示 |
| 消费者/订阅用户 | 查看已发布报表、指标和服务结果 | 运行时重新校验当前有效权限；订阅不是权限快照 |

**通用权限验收**：对每个读/写/执行接口分别使用平台管理员、资源 owner、被授权用户、未授权用户、已撤权用户验证；不能仅验证前端菜单是否隐藏。未授权时不返回敏感资产名称、字段、行数据或凭据细节。

### 4.4 数仓存储、批量入仓与分析消费

| ID | 功能点 | 当前状态 | 优先级 | 验收标准 |
|---|---|---|---|---|
| WH-001 | 数仓需求与目标引擎决策 | 待新增 | P0 | 形成数据量、增长、刷新时效、并发、保留、恢复、成本和运维能力评估；明确业务源、平台元数据库、分析目标的边界以及组织/租户权限传递；记录引擎选择 ADR，不预设具体产品。 |
| WH-002 | 独立分析目标与分层存储 | 待新增 | P0 | 配置独立分析目标及最小权限账号；ODS/DWD/DWS/ADS 分层约定、分区、生命周期、备份和恢复路径可查；禁止将业务明细写入平台元数据库。 |
| WH-003 | 全量与批量增量入仓 | **S2+S3-08 MVP** | P0 | CH/Doris/StarRocks 装载 FULL REPLACE + INCREMENTAL MERGE（水位+业务键）；失败不丢旧表；Doris/SR 经 `MysqlProtocolBatchPublisher`。管道默认仍 CH；CDC/实时流不属于此项。 |
| WH-004 | 数仓分层建模与首个主题模型 | 待新增 | P0 | 定义事实/维度、粒度、业务主键、历史变化、迟到数据和空值语义；模型版本可追溯至源资产和字段；重复、更新及历史数据场景结果正确。 |
| WH-005 | 物化发布与安全回滚 | 待新增 | P0 | 加工结果先写 staging，校验结构、行数和质量后原子发布；同一版本/分区重跑幂等；失败保留旧版本并能回滚；写入目标必须显式授权。 |

## 7. 分阶段交付与阶段门

| 阶段 | 功能范围 | 阶段完成门槛 |
|---|---|---|
| **0：现状与基线** | 固定 BI 资产所有权、URN、权限边界、状态机、模块/表命名；整理未提交修复和清单任务 | 架构评审通过；数据模型与权限码清单完成；关键未提交启动修复已评审、回归并纳入提交；无不明重复表 |
| **1：资产目录/元数据** | PLAT、SRC 的目录、扫描、快照、差异和 BI 资源引用 | 至少两类真实数据源；目录授权负向测试通过；扫描失败保留旧快照；结构差异能展示 |
| **2：最小数仓与批量入仓** | 独立分析目标、全量/批量增量、ODS/DWD/DWS/ADS 逻辑分层、物化、核对、新鲜度和 BI 试点 | 至少一个真实源入仓；回补幂等；源目标差异可追查；BI 指标和权限对账；恢复路径通过 |
| **3：质量治理** | DQ 规则、试跑、全量/采样、计划、结果、趋势、告警闭环 | 源/数仓限额、超时、取消验收；结果权限通过；失败重试幂等；质量通知实测 |
| **4：加工 DAG** | 流程编辑、版本、任务调度、节点重试/取消、发布和回放 | 相同 revision 可复跑；失败不覆盖旧输出；从节点重放正确；发布到数仓可核对 |
| **5：变更安全/指标** | 影响分析、迁移计划、回滚、指标定义与消费者追踪 | 破坏性变更阻断；兼容建议可人工确认；回滚实测；指标跨图表/API 口径一致 |
| **6：数据服务** | API、Key、配额、调用日志、导出/订阅 | Key 吊销、权限撤销和限流快速生效；真实通知投递；API/导出继承行列权限 |
| **7：规模演进** | Worker 隔离、通用湖仓、对象存储物化、CDC/实时流和更多数据服务 | 有压测和成本报告证明触发条件；故障恢复、重放、容量和运维演练通过 |

## 8. 发布验收清单

一次平台功能发布至少逐项确认：

- [ ] 前端页面、空/错/加载/无权限状态和操作文案完成。
- [ ] 后端接口对未授权/撤权/伪造资源 ID 执行拒绝测试。
- [ ] 新增数据库迁移通过空库初始化、旧库升级、重复启动和升级失败恢复验证。
- [ ] 核心路径有自动化单测和集成测试，外部依赖测试注明 Mock 或真实实例。
- [ ] 运行日志、审计、指标、Trace 中无密码、Token、API Key、业务数据明细或敏感 SQL 参数。
- [ ] 超时、取消、重试、幂等、限流、失败保留旧版本均覆盖。
- [ ] 数据源范围、行列权限、组织/租户边界从 UI、API、后台任务分别验证。
- [ ] 文档列出新增配置、权限码、部署/回滚、数据保留和现场验收步骤。
- [ ] 发布说明使用“已实现 / 自动化通过 / 真实环境通过 / 未验证”四种不同口径，不混为一谈。
