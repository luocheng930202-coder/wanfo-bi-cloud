# 数仓数据集组织范围绑定

> 关联任务：DP-041。当前实现以本地 RuoYi 单体集成和 ClickHouse `retail-v1` 模型为验收目标。

## 能力范围

- V37 新增数据集→模型/租户字段/组织字段绑定，以及模型版本下的若依组织主体→数仓 `tenant_id`、`org_id` 映射。
- 数据集管理的“数仓范围”操作只对管理员显示。绑定前，字段必须存在于该物理表数据集；只支持表数据集，不猜测 SQL 数据集的业务字段语义。
- 查询和已保存数据集预览由服务端解析当前登录用户的若依部门子树，找出已登记映射并注入参数化租户过滤和组织 `IN` 条件。客户端图表筛选不能覆盖或放宽此服务端条件。
- 填报写入/可见性校验复用相同范围。管理员沿用已有 `bi:resource:admin` 豁免。
- 绑定字段失效、登录组织无法解析、没有映射或映射涉及多个租户时，非管理员结果为空或请求拒绝；不会回退为 unrestricted 查询。
- 管理员新增、移除数据集绑定和组织映射会写入目录审计，不记录连接凭据或业务行。

## 管理员配置

1. 应用 BI Flyway `V37__dp_warehouse_row_scope.sql` 并部署包含 DP-041 的后端、前端。
2. 在“数据集”中对使用数仓 ADS/DWS 物理表的数据集点击“数仓范围”。绑定模型版本，例如 `retail-v1`，并选取数据表内真实的租户键字段和组织键字段（例如 `tenant_id`、`org_id`）。保存即启用强制范围过滤。
3. 对同一模型版本逐一添加若依组织映射：搜索目录中的组织主体，填入该主体对应的 `tenant_id` 与仓库 `org_id`。父部门用户会获得其若依部门树中所有已配置组织节点的集合；不同租户混入同一子树时访问失败关闭。
4. 最少验证：省级用户只能看到该省及映射市县；市级只能看到本市及其已映射县；县级仅看到本县；其他租户记录不可见；无映射/无部门用户返回空结果；管理员可按既有权限查看完整数据。

## API

- `GET|PUT|DELETE /bi/warehouse/scopes/datasets/{datasetId}` 管理数据集范围绑定。
- `GET|POST /bi/warehouse/scopes/{modelVersion}/organizations` 查询/新增组织映射。
- `DELETE /bi/warehouse/scopes/{modelVersion}/organizations/{id}` 移除组织映射。
- 所有配置接口需要 `bi:resource:admin`；映射主体必须是已登记的 RuoYi organization principal。

## 边界与验收限制

- 当前范围基于 RuoYi `sys_dept` 部门树；自定义组织目录、跨部门授权、多个 tenant 的单一组织树需要后续扩展明确模型，不能隐式推导。
- 未映射的下级部门不会扩大可见范围；管理员应完整配置需要开放的部门。变更前应在本地或验收环境先完成最小权限回归。
- V37 和前后端代码已完成编译检查；仍需重启/部署服务应用 V37，再使用真实非管理员省/市/县身份完成正反向查询验收。当前验收登录是管理员，且本地 RuoYi 部门与合成仓库组织没有业务映射，因此本任务尚未关闭。
