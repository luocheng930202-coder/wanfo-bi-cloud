## 1. 排期假设

基线按1名后端、1名前端全职，数据/测试角色合计约0.5人投入；产品、安全、运维按阶段参与。表内工时是规划估算，不是实测或人员承诺。每周5个工作日，不计法定假日；每阶段预留约20%容量用于兼容性、缺陷、权限回归和验收。

首轮 R0～R2 计划8周，先交付只读助手，再交付问数制图。若仅1名全栈人员持续开发，建议按12～16周估算首轮；AI 编码辅助不替代业务口径确认与真实环境验收。模型采购/部署、安全批准和业务反馈延迟会影响关键路径。

## 4. 阶段验收门

| 门禁 | 必须满足 | 不满足时处理 |
|---|---|---|
| G0：开工范围 | 提供方、出域、试点负责人、语义范围与预算明确 | 可做模拟开发，阻断真实业务数据出域 |
| R0退出 | 权限工具链、版本、预算、固定题库可用 | 不开放自由问数 |
| G1：只读助手 | 40业务案例≥90%正确且证据完整；≥30安全案例全通过；模型故障不影响BI | 修复/缩小认证范围，不扩大用户 |
| G2：问数制图 | 60固定+20改写；首轮≥90%，限定修复后固定基准全符合；20图表合法；三次重复评测、安全全通过 | 保留只读能力，问数继续试点 |
| G3：辅助生产 | 建模/治理/诊断各10正负场景，确认操作不绕原流程 | 仅展示建议，禁用工具写操作 |
| G4：大屏与分析 | 布局绑定合法、可编辑可撤销；异常算法和回测明确 | 保留模板推荐，禁用自动生成或异常推送 |

任何权限泄露、密钥泄露、未授权出域均一票阻断。性能目标与准确率样本必须公开测试范围，不外推为所有业务的生产保证。

## 5. 后续实施顺序

R3建议先数据集助手（AI-024），再治理（025），再运维（026），最后统一回归（027）。R4先定义模板/组件契约（028）再实现生成（029）；异常分析（030）单独验证后统一验收（031）。

暂缓：任意生产SQL执行、自动改库、无人审核发布/重跑、通用多Agent、模型微调、3D模型自动生成、全域跨库自由问答。新增需求先调整任务和资源，不挤占安全验收。

## 6. 关键风险与应对

- 语义不完整：优先认证小范围指标；歧义必须澄清，关系不安全则拒绝。
- 模型不稳定：冻结配置/提示版本，三次评测；升级走回归，保留旧配置。
- 既有契约变化：W1核对实际代码，增加适配层和契约测试，不复制执行器。
- 费用过高：最少上下文、限制工具步数和结果规模、预算硬停；检索缓存必须隔离权限。
- 样本代表性不足：业务人员维护失败案例，合成数据测边界，试点实测另记。
- 外部依赖未就绪：模拟开发可继续，但真实模型/业务/生产验收分别标记，不能合并为“已完成”。
