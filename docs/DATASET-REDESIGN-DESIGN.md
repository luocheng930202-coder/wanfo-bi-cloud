# 万佛数据平台数据集整体改造设计方案

- 编制日期：2026-11-05
- 状态：设计建议，尚未实施
- 范围：数据集管理、建模、字段语义、预览、版本与下游兼容；复用平台四主题及顶部模块导航。
- 研究方式：本系统前后端源码、本地 DataEase V3 核心源码、运行中的 DataEase 页面只读检查。未执行数据库写入、未修改 DataEase、未提交代码。

## 1. 结论与目标

建议把当前“目录列表＋多个独立弹窗”升级为“数据集资源浏览器＋独立建模工作区”。借鉴 DataEase 的交互组织与建模抽象，在本平台中独立实现，继续使用已有数据源、Calcite/数据库查询适配、权限、质量、数仓和运维能力。

本次改造不是简单换皮，也不是把 DataEase 数据集模块直接搬入。核心目标：

1. 从选源、选表、关联、字段整理、计算、过滤到预览、保存，在一个连续工作区完成。
2. 编辑过程不修改当前生效定义；确认变更后原子生效，避免图表读取到半成品。
3. 同一字段跨编辑保持逻辑身份；重命名、删列、改类型、改粒度前明确影响范围。
4. 预览、图表、看板、导出、订阅与 API 使用一致的数据集定义和权限语义。
5. 建模应主动提示一对多放大、类型冲突、空值和聚合口径，而不只是生成 SQL。
6. 旧数据集与图表能够逐个迁移、灰度启用和回退。

## 3. 本系统现状与差距

### 3.1 已具备，不重复建设

### 3.2 本轮确认的主要差距

1. 创建、建模、字段、质量与权限分散在多个弹窗，用户难以形成一个完整定义。
2. 当前字段改动和关联操作通过独立接口即时生效；缺少统一草稿、预览与原子应用语义。
3. `applyJoin` 会删除旧关联生成字段再插入新字段，字段数据库 ID 可能变化。当前图表还使用字段名，因此不能只新增 fieldId 就认定兼容；必须同时保护旧字段名/别名和计算引用。
4. 多关联模型缺少显式节点 ID、表别名、多字段条件、布局信息和关系基数声明。
5. 预览限制是 100 行，不能用预览结果代替全量质量、唯一性或性能结论。
6. 原始物理类型、分析类型、日期粒度与展示格式缺少完整分层契约。
7. 缺少统一的生效版本、并发编辑保护、版本差异和适用于数据集定义的回滚流程。
8. 是否所有操作均正确失效缓存、隔离用户上下文，需要在改造中专项审计，不能仅凭编辑成功判定查询一致。

## 4. 产品与页面方案

### 4.1 入口和导航

仍放在“数据开发 → 数据集”。管理页保留平台顶部导航和四主题。建模进入同一浏览器内的工作区，不新开窗口，不改变旧书签兼容。

建议新增路由：

- `/bi-admin/dataset`：资源浏览器，支持 `?datasetId=` 选中。
- `/bi-admin/dataset-workspace/new`：新建。
- `/bi-admin/dataset-workspace/:id/edit`：编辑草稿。
- `/bi-admin/dataset-workspace/:id/view`：查看生效结构，权限只读。

旧“创建/建模”按钮先通过功能开关迁移到工作区；保留旧实现作为灰度回退。切换前有未保存状态提示。

### 4.2 资源浏览器

- 左侧：目录树、搜索、目录增删/移动；列表继续支持批量管理和明确空目录删除约束。
- 右侧头部：数据集名称、类型、数据源、负责人、生效版本、状态、编辑/更多操作。
- 主区域页签：数据预览、字段结构、依赖关系、质量记录、设置。
- 预览明确显示“当前权限下的前 N 行”、耗时、定义版本、数据获取时间；精确总行数独立按需查询，未查时不显示伪总数。
- 新建图表/看板时传入 datasetId，直接进入已绑定数据集的分析流程。
- 权限不足、无字段、无数据、数据源不可用、数仓门禁阻断分别展示，不能统一为“暂无数据”。

### 4.3 建模工作区

```text
返回 | 数据集名称 | 草稿/生效版本 | 校验 | 保存草稿 | 应用变更
──────────────────────────────────────────────────────────
数据源 / 库 / Schema / 搜索  | 表与关联画布       | 选中项属性
表和视图 / SQL 节点          | 节点别名、连接关系 | 关联类型/字段
──────────────────────────────────────────────────────────
数据预览 | 字段管理 | 计算与分组 | 过滤 | 校验问题
字段角色、字段属性、样本表、耗时/版本/限制、错误定位
```

数据源选择应分别处理 catalog 与 schema：PostgreSQL 的数据库与 schema、SQL Server 的 catalog/schema、Oracle owner、ClickHouse database，不再要求所有类型套用“数据库”一项。UI 根据连接器能力显示，不让前端猜标识符规则。

画布交互：拖表或双击添加、选择两表建立关联、点击边编辑条件、缩放/适应、删除前检查字段与关系引用。键盘操作提供同等入口。小屏收起属性栏和表列表，不承诺手机上高效编辑大型模型。

### 4.4 字段管理与计算

- 字段来源、物理名称、稳定逻辑名称、显示名称、物理类型、分析类型、角色、默认聚合、日期粒度、展示格式、分组、是否输出、敏感等级。
- 批量改角色、分组、排序、显示名；隐藏输出不等于授权脱敏。
- 聚合仅建议，不强制所有数值 SUM；订单号、学校编码即使数值存储也应建议维度。
- 计算编辑器包含字段、函数分类、参数说明、校验与错误位置、结果类型。
- 第一阶段限行级表达式，复用 CalcFormulaCompiler 白名单；聚合指标继续由指标/图表层负责。窗口函数、跨层聚合另立能力。
- 分组字段通过受控 CASE 或映射定义实现，保留“其他”和 NULL 规则。
- 安全转换产生新逻辑字段或明确类型变更；不把更改标签当作实际类型转换。

## 5. 建模与执行设计

### 5.1 同源优先的节点模型

V1 在现有同一数据源/catalog 边界内升级，不借 UI 改造开放跨源。节点区分 TABLE、SQL；暂不允许任意数据集套数据集，以免出现循环与权限转移。

V2 建议定义：

```json
{
  "schemaVersion": 2,
  "executionMode": "LIVE_SINGLE_SOURCE",
  "rootNodeId": "table-orders",
  "nodes": [{"id":"table-orders","kind":"TABLE","datasourceId":12,"catalog":"demo","schema":"public","table":"orders","alias":"o","position":{"x":80,"y":80}}],
  "joins": [],
  "fields": [],
  "computedFields": [],
  "filters": [],
  "layout": {"zoom":1}
}
```

字段定义至少包含 fieldKey(UUID)、legacyFieldId、legacyName、sourceNodeId、sourceColumn、logicalName、label、role、logicalType、expressionAst、enabled、order。关系包含 edgeId、leftNodeId、rightNodeId、joinType、conditions[{leftFieldKey,rightFieldKey,operator}]、declaredCardinality。

首版关系按有根无环树编译，避免任意 DAG 造成不确定 JOIN 顺序；画布不是无限制图查询。多字段条件先支持等值 AND，自关联依赖不同节点 ID/别名。环、重复边、断开的节点、失效键、类型不兼容必须阻止应用。现有 8 条关联和 200 输出字段限制在容量验证前保留并显示。

### 5.2 关系类型与粒度

- 基础 LEFT/INNER/RIGHT；FULL 由方言能力决定，不能只加一个前端选项。
- 声明 1:1、N:1、1:N、N:N，告知检测是抽样还是精确检查；声明不是事实保证。
- 多事实表按学校和日期关联前，应先预聚合至共同粒度；系统提示一对多扇出，不擅自 DISTINCT 或求和来“修正”业务数据。
- 暂不提供笛卡尔积；NULL 连接键遵从 SQL 语义，不默认把 NULL 当同值。

### 5.3 纵向追加与跨源分阶段

后续 UNION ALL 为独立 APPEND 节点：按字段映射追加，要求类型兼容，显式缺失列填 NULL；UNION 去重单独配置，提示开销。

跨源需独立执行策略：同源 JDBC 下推；获准的关系型连接器可进入受控 Calcite 联邦计划；API/文件依赖已治理的快照；大体量跨源优先经加工/装载进入共同数仓后建模。不能承诺任意源互相拖拽后实时关联。

引入连接器能力表：schema 浏览、预览、标识符引用、函数、JOIN 类型、SQL 节点、取消、行数限制、联邦/快照支持。无能力时给出明确禁用原因。

### 5.4 查询公共链路

```mermaid
flowchart LR
  A[草稿或生效定义] --> B[服务端校验与权限]
  B --> C[标准模型与字段绑定]
  C --> D[方言编译 / 执行策略]
  D --> E[数据库或受控查询执行器]
  E --> F[预览 / 图表 / 看板 / 导出 / 订阅 / API]
```

预览与正式查询复用同一语义编译器。只改变 limit、超时与取样上下文，不允许预览绕过权限或门禁。分页无排序时说明非稳定样本；需要稳定分页时选定排序键，不默认对未知大表执行 OFFSET 深分页。

预览默认 100 行，设置服务端行数、时间、扫描与并发上限；不默认 COUNT(*)。前端防抖、取消旧请求、响应 generation/revision 核对；只有执行器真的支持取消时才宣称数据库查询被停止。全量质量继续走既有任务体系。

## 6. 草稿、保存与生效

状态：不存在 → 草稿 → 校验通过 → 应用生效。每次应用创建不可变 revision；旧生效版本在草稿编辑时继续服务。

1. 加载包含 activeRevision、draftRevision、expectedVersion 的完整定义。
2. 本地修改进入脏状态，统一保存草稿；字段/关联不再逐项直接写生效表。
3. 校验返回 issues、编译 SQL、输出字段映射、影响摘要与 definitionHash。
4. 应用请求携带 expectedVersion 和定义指纹；服务端重做授权及关键校验，防止拿旧报告应用新定义。
5. 元数据事务原子写入定义/字段映射、revision、active 指针及审计；不把远程查询包在长数据库事务中。
6. 提交后按 revision/hash 精确隔离缓存，通知血缘与依赖检查；多实例依赖版本号而非仅进程内事件。
7. 并发修改返回 409，展示差异与重新加载入口，不能静默覆盖。

“应用”是让数据集变更生效，不等同于授权、分享或执行全量同步。首版不强制审批流，但对破坏性引用变更设门禁。

## 7. 字段兼容、影响和回滚

- 迁移已有数据集保留 id、原字段 id/名称、关联生成别名、显示名及 extFormula；新增 stable fieldKey 作为长期身份。
- 现有图表按字段名绑定，兼容编译层仍输出旧逻辑别名；逐步为图表、指标、权限和 API 增加 fieldKey，不能一次性替换所有引用。
- 重命名显示名不等于改 logicalName；默认只改 label。
- 删除/停用字段、缩窄类型、改公式输出类型或改关系粒度，返回依赖对象清单。查询相关图表、看板、指标、订阅、API、数据策略、数仓作用域绑定与计算字段依赖。
- 有生效引用的破坏性变更默认阻止；需要映射替换或显式协调迁移，不能只点确认忽略。
- 回滚通过创建“恢复自 revision N”的新 revision，不倒改历史。再次校验当前物理结构、权限和门禁；原表已删时应拒绝，不承诺任何历史版本都能运行。
- 回滚影响定义，不回滚源库数据、已发订阅附件或数仓物理数据。
- 复用现有结构迁移计划和审计，补充数据集 revision 级快照，不另建两套相互矛盾的字段映射。

## 8. 元数据建议（逻辑表名，开发前核对现有迁移）

| 调整 | 作用 |
|---|---|
| bi_dataset_table 增加 model_schema_version、active_revision、lock_version 等 | 保留旧 ID/type/datasource 字段，增加生效指针与并发控制 |
| bi_dataset_revision | dataset_id、revision、parent_revision、definition_json、definition_hash、compiled_plan、output_schema、创建/应用审计；revision 唯一 |
| bi_dataset_draft | dataset_id、owner、expected_active_revision、draft_version、definition_json；首版一份共享草稿并发锁，不混用多人个人草稿 |
| bi_dataset_field 增加稳定 field_key 等 | 保留旧记录与别名；类型和字段属性分阶段补充 |
| bi_dataset_revision_field / revision 中 output_schema | 保留版本字段快照；二者择一作为真源，避免重复权威数据 |
| validation report（可先短期存储） | 指纹、错误/告警、检查上下文及过期时间，不缓存明文凭据或全量样本 |

节点和关系首版随 versioned JSON 存储，暂不额外拆多张节点/边表。SQL 是派生产物，持久化便于审计，但执行前仍检查连接与权限上下文，不信任前端传来的 SQL。

| GET /bi/dataset/{id}/workspace | 生效/草稿概要、可操作能力、完整模型 |

| PUT /bi/dataset/{id}/draft | 带 expectedDraftVersion 保存 |
| POST /bi/dataset/{id}/draft/validate | 返回字段类型、错误/告警、定义指纹与影响 |
| POST /bi/dataset/{id}/draft/preview | 服务端校验后受控预览，不写生效版本 |
| POST /bi/dataset/{id}/draft/apply | expectedActiveRevision + draftVersion，原子生效 |
| GET /bi/dataset/{id}/revisions | 版本列表与差异 |
| POST /bi/dataset/{id}/restore | 从目标版本创建新草稿，检查后应用 |

迁移期间旧即时写入接口必须通过同一 revision 服务，或明确只供旧模式数据集使用，不能绕过并发/影响门禁。服务端每个接口校验操作权限和具体资源权限；新增 edit/apply 等能力前核对现有权限体系并制定兼容映射。

## 10. 安全与性能必须保留的边界

- 查看定义、编辑、查询、授权、导出、消费是不同能力；画布节点菜单不能推导出资源权限。
- 样本与正式查询在服务端应用数据集行列策略、租户组织范围。关联涉及多个受保护来源时逐来源执行作用域约束，并明确外连接过滤位置；不能只靠最终 WHERE 或前端隐藏列防泄漏。
- 字段改名/删除不得让 tenant/org 绑定失效后降为全量访问；无法映射时拒绝应用或拒绝查询。
- 缓存键包含生效 revision/定义 hash、查询和参数、数据权限上下文、数据源/快照版本等必要信息；权限变更有失效策略。
- SQL 节点保持受限管理能力、单条只读语句校验与参数绑定，不拼接任意请求值；表达式继续白名单。
- 元数据加载按 schema/表搜索分页或分批，不一次加载所有库全部字段；图预览不自动触发全量扫描。
- 数据集 LIVE、缓存和物化是不同模式。保存定义不会自动建立实时 CDC，也不承诺实时性。
- UI 继承四主题；SQL 编辑器、预览表格、下拉层、错误面板及画布空态共同验收。发布/分享作品的主题不受影响。

### 第六批：WHERE 条件 SQL 参数（2026-11-05）

自定义 SQL 增加“变量语法”和“SQL 参数”设置，兼容以下写法：

```sql
SELECT * FROM table_name
WHERE $DE_PARAM{ name = substring('$[PARAM1]',1,5) }
  AND $DE_PARAM{ name IN ($[PARAM2]) }
```

- 参数名称从 SQL 自动识别、去重，可设置显示名称、文本/数值/日期/日期时间、单值/多值、必填、默认值及默认值作用范围。
- 多值每行一个值，不需要 SQL 引号，仅允许用于 IN / NOT IN 值列表。带引号的单值支持 substring、LIKE 字符串组合等表达式。
- 默认值范围分为“预览及查询”和“仅编辑预览”；本次预览值不保存，保存的是原始 SQL 模板与参数定义，避免把测试条件固化进 SQL。
- 可选参数缺值时，整个对应 `$DE_PARAM{...}` 条件替换为 TRUE；必填参数缺值报错。一个条件块引用多个参数时，任一缺值都会跳过整个条件块。
- 服务端通过语法树验证每个 SELECT 的 WHERE 位置，拒绝 SELECT 列、JOIN ON、HAVING、ORDER BY 等位置中的变量；嵌套查询按各自 WHERE 验证。
- 值使用 PreparedStatement 绑定，显式类型转换解决 Calcite 对函数参数的类型推断限制；参数不可替换字段或表名。
- 已保存数据集的预览页提供“SQL 查询参数”，可覆盖参数、清空可选参数或恢复默认。图表查询接口支持 QueryModel.sqlParameters，图表/看板运行默认使用查询范围默认值；看板筛选组件到 SQL 变量的可视化映射配置仍待后续实现。
