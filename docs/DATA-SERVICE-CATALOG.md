# 数据服务目录盘点（DP-028）

## 目录原则

数据服务目录复用现有资源定义、授权、版本、订阅和导出事实，不重复创建 BI 查询、导出任务或报表订阅表。目录中的服务分成“指标查询 API”“受控只读 SQL”“文件导出”“定时报表订阅”四类，分别明确凭据、资源授权、版本、限额、审计、撤销和保存期限。新建面向外部系统的 API 统一从已发布指标开始；原有 BI 管理端 API 仍按会话权限保护，不视为外部稳定 API。

## 现有能力映射

| 服务能力 | 现有事实/API | 权限与生命周期 | 对外化约束 |
|---|---|---|---|
| 指标读数 | `bi_metric`、`bi_metric_history`、`bi_metric_usage`；`POST /bi/metric/code/{code}/data` | `bi:metric:query`、指标/数据集资源授权；发布快照冻结，取消发布受消费者约束 | 使用受控 API 定义绑定已发布指标；不让调用方提交任意查询模型 |
| BI 工作台查询 | `POST /bi/chart/query`、`POST /bi/dataset/{id}/preview` 等 | BI 登录会话、功能权限、资源权限、数据策略 | 属于内部交互接口；外部 API 不直接代理原始 SQL、调试执行 SQL 或预览接口 |
| 通用 SQL 查询 | `POST /bi/query` | 旧接口在控制器中仅解析 SELECT 并限制超时/行数 | 不纳入新服务目录，外部化前必须替换为明确的数据集/指标模型和受控授权 |
| 导出 | `bi_export_job`；`/bi/export` 提交、状态、取消与下载 | `bi:export:*` 和资源授权；异步任务、状态及文件下载 | 复用现有作业和存储；令牌/下载地址须短时有效，不复制数据文件 |
| 报表订阅 | `bi_report_subscription`、运行/通知历史；`/bi/subscription` 与站内通知/审计接口 | `bi:subscription:*`；时区、模板、通知渠道和管理员审计 | 复用当前订阅生命周期，通知重试进入 DP-030，不新建平行调度表 |

## 统一 API 生命周期

草稿创建 → 绑定已发布指标 → 校验数据权限和服务上限 → 生成只展示一次的 API Key → 调用与最小审计 → 轮换/撤销。服务版本独立于指标版本；发布时记录冻结的指标版本、最大单页行数、超时、配额和服务说明。调用日志只记录服务/密钥标识、时间、状态、耗时和返回行数，不记录请求参数、响应行或凭据。密钥按 SHA-256 哈希保存，明文只在创建/轮换时展示一次。

## DP-029 接入边界

第一阶段只允许只读访问已发布指标，支持 `page`/`pageSize`、服务级超时和配额。租户/组织行过滤继续使用指标所有者经宿主系统实时复核的权限上下文；宿主账号停用或授权撤回后，Key 调用随之失败。此阶段不支持任意 SQL、传入字段筛选表达式、变更指标定义或跨服务聚合。

管理端 API：`GET/POST /bi/data-apis`、`PUT /bi/data-apis/{id}`、`GET /bi/data-apis/{id}`、`POST /bi/data-apis/{id}/publish`、`POST /bi/data-apis/{id}/keys/rotate?expiresInDays=90`、`POST /bi/data-apis/{id}/keys/{keyId}/revoke`、`POST /bi/data-apis/{id}/disable`。管理操作仅管理员可用。创建/发布需要绑定已发布指标；发布结果的 `oneTimeKey` 只显示一次。

调用端点：`POST /bi/open-data/{apiCode}?page=1&pageSize=100`，请求头 `X-Wanfo-Api-Key: <创建/轮换时返回的Key>`。响应只含列、行、行数、耗时和分页信息；不返回执行 SQL 和绑定参数。调用审计仅保留 API/Key ID、状态、耗时和返回行数。固定窗口配额以数据库计数保证跨实例一致；分页最大偏移 1,000,000，页大小不超过 API 设置或系统 1,000 行上限。API 目前由发布时的指标创建者权限身份实时复核数据权限；若创建者离职或授权变更，调用会失败，需管理员重新创建绑定身份的 API。
