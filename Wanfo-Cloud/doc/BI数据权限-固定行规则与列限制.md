# 固定行规则与列限制（2026-10-16）

本批按 WBS S8-T12/T14/T15/T16 与 S4-T01/T02/T03 推进已保存表数据集的安全取数。管理员在“数据集管理 → 数据权限”中选择 BI 主体、字段及限制。配置暂要求 `bi:resource:admin`，数据集所有者和普通授权管理者不能改变限制。配置接口为 GET/POST `/bi/dataset/{id}/policies`，DELETE `/bi/dataset/{id}/policies/{ruleId}`。

## 规则语义

| 项目 | 当前约定 |
|---|---|
| 主体 | 若依适配为内部 BI 用户、角色、直接部门主体；核心不引用 sys_* 或若依角色 ID |
| 固定行规则 | EQ、NE、GT、GE、LT、LE、IS_NULL、IS_NOT_NULL；常量绑定为 JDBC 参数，不支持 SQL 表达式 |
| 多主体冲突 | 当前用户、所有角色和直接部门命中的行条件全部 AND；条件矛盾返回空结果，不将多角色合并成全量访问 |
| 无命中规则 | 在已获资源 view/query 的前提下不额外限制；规则本身不授予资源权限 |
| 列冲突 | DENY 隐藏优先于 MASK；多个主体命中的列限制合并 |
| 脱敏 | 常量 `***` 替代，在投影 SQL 中完成，应用不读取原始字段值；空值也替换，不保留空值分布 |
| 所有者 | 普通所有者仍受命中规则限制 |
| 管理员 | `bi:resource:admin` 豁免数据限制，可配置及调试；此功能码应仅授予可信管理员 |
| 生效 | 每次请求读取最新规则，不缓存结果；规则变更对后续请求立即生效，不中断已开始的查询 |

SQL 比较沿用数据源的类型、排序规则和 NULL 语义；数值字段绑定 BigDecimal。空字符串与 NULL 分开。失效字段、无效数值及全部字段隐藏均拒绝查询，不退回 SELECT *。新增/删除记录包含真实创建人，删除数据集时在同一事务清理规则。

## 执行入口

- 保存后的数据集预览：先检查功能及数据集 view/query，再解析当前主体规则。行过滤在 LIMIT 前执行，隐藏字段从列描述和值同步剔除，脱敏直接在数据库投影中替换；不返回执行 SQL/参数。
- 数据集定义：普通用户不返回完整 unionSql，隐藏字段从字段列表及字段计数移除。
- `/bi/chart/data` 与 `/bi/chart/dataset/{id}/fields`：要求 `bi:dataset:query` 和资源 view/query。固定条件包装在聚合输入范围，参数按 SQL 出现顺序绑定。隐藏、脱敏字段不能作为维度、度量或过滤字段；排序须属于当前查询输出。普通用户看不到执行 SQL 和参数。
- `/bi/chart/compile`、SQL 型数据集及原始 SQL 仍仅限管理员，未开放任意 SQL。图表查询接口可供有权数据集探索使用，不代表图表配置保存和看板授权完成。
- 保存前的原始库表预览遵循数据源 `model` 权限，不执行某个尚不存在的数据集的规则。限制使用者不要获得原始数据源建模权限；不将数据集规则称为数据库级隔离。

本批没有目录继承、部门后代、属性变量、OR 规则组、自定义脱敏算法、导出策略或看板代查身份。现有 QueryModel 为白名单模型，过滤树及复杂计算仍按 WBS 后续实现。今后新查询、缓存及导出入口须接入同一主体/资源/数据策略后再开放。

## 升级与边界

V6 位于 `db/migration/bi`，增加 `bi_dataset_policy`，主体关联 `bi_principal`。不修改 V1～V5，不把历史权限表的 `role_id` 自动解释成 BI 主体 ID。升级前备份；已有规则需明确迁移，不能直接复制外部 ID。若依会话中的角色与部门成员关系仍沿用登录态快照，成员变更后需重新登录。

当前开发库 V5→V6 已升级；回退应用可以保留 V6 表，但旧应用不执行新规则，已有普通角色访问应先回收再回退。不能用删除 Flyway 历史的方式回滚。独立部署继续复用 `DatasetDataPolicy`、`DataPolicyCompiler` 和 BI 内部主体，只替换宿主身份及功能权限适配；独立部署包仍是 S11 后续事项。
