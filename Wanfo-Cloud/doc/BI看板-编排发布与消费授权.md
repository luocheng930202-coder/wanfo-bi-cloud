# 看板编排、发布与消费授权（2026-10-16）

本批推进 S7 基础闭环，入口 `/bi-admin/dashboard`。旧 `/bi/dashboard` 书签重定向到新菜单，不再固定展示开发占位页。前端继续使用若依菜单与功能权限，BI 内部资源和数据规则不依赖若依类型。

## 编排与发布

新建看板，选择有权查看和查询的已保存图表，加入画布，调整组件标题、位置及大小，保存草稿后发布。当前为 12 列 GridStack 栅格，最多 20 个图表；组件宽度 2～12 列、高度 2～12 行，画布最多 120 行，不允许重叠。可拖动标题移动组件、拖动边角缩放，也可通过宽度、高度、上移和下移控件编排。

草稿可为空，发布至少一个图表。保存、发布、下线采用版本条件更新，过期版本返回 code 409；发布前重新验证全部图表及数据集访问资格。引用失效时拒绝保存/发布，不默默跳过无权组件。

发布复制当前草稿及所引用图表的完整查询配置，形成服务器端快照。后续修改草稿、修改独立图表，不改变当前发布版本；重新发布时才替换快照。下线清除当前发布入口，后续 manifest 和取数请求拒绝访问。当前仅保留草稿与最新发布快照，历史发布记录、回滚及撤销重做尚未实现。

草稿及发布快照分别登记图表/数据集引用。已发布版本仍引用的图表，即使从新草稿移除，也不能直接删除；重新发布或下线并移除草稿引用后才释放保护。删除看板会释放两类绑定。数据集删除同样检查看板引用。

## 功能权限、资源权限与消费资格

| 能力 | 若依功能码 | BI 资源动作 |
|---|---|---|
| 看板列表 | `bi:dashboard:list` | 看板 `view` |
| 创建草稿 | `bi:dashboard:add` | 新看板归当前用户 |
| 读取/更新草稿 | `bi:dashboard:edit` | 看板 `view` + `edit` |
| 发布/下线 | `bi:dashboard:publish` | 看板 `view` + `publish` |
| 读取发布内容与组件数据 | `bi:dashboard:consume` | 看板 `view` + `consume`；取数还需数据集 `consume` |
| 删除看板 | `bi:dashboard:remove` | 看板 `view` + `remove` |
| 授权 | `bi:dashboard:grant` | 看板 `view` + `grant` |

编排与发布所引用的图表还要求当前作者具备图表 list/query 功能与资源 view/query，以及原有数据集探索资格。发布不是把作者身份交给查看者。

配置纯看板使用者的步骤：

1. 在若依角色管理分配看板菜单及 `bi:dashboard:consume`，修改后重新登录。
2. 在看板“授权”中向对应 BI 用户、角色或直接部门授予 `view` 与 `consume`。
3. 在所用数据集的“授权”中向对应主体授予“看板消费（不可自由查询）”，即资源动作 `consume`。
4. 按业务配置该主体的固定行规则、字段隐藏或脱敏。看板取数继续按查看者的当前主体执行这些规则。

无需给纯使用者数据集列表、预览、自由图表查询、库表建模、图表编辑等功能，也无需数据集 view/query 资源资格。单独授予看板权限不自动扩大到数据集；没有数据集 consume 时显示组件不可用。

数据集 consume 只允许通过有权看板的发布绑定取数。组件请求必须带当前 revision，服务端从快照定位 key 和查询定义；请求体中的数据集、字段、过滤或 SQL 覆盖均不起作用，不能通过猜测组件 ID 查询其他模型。未发布、已下线、版本不匹配或无权看板均在执行查询前拒绝。

每次请求重新检查看板权限、数据集消费资格和当前用户行列规则。固定行条件仍在聚合前应用；隐藏/脱敏字段不能被用作分组、度量或过滤，旧快照选择了新受限字段时拒绝取数。管理员豁免数据规则仍遵循前批约定，普通看板使用者不会获得管理员或发布者上下文。

撤销看板 consume 或数据集 consume 会阻止后续对应请求，不中止已经执行中的查询，也不能收回已显示的结果。数据集 consume 是资源级资格，可能服务多个看板，因此撤销某个看板权限或下线时，不自动撤销全局数据集消费资格。若依角色功能和成员关系仍沿用登录态快照。

## 接口与数据边界

| 接口 | 用途 |
|---|---|
| GET/POST `/bi/dashboard` | 列表/新建 |
| GET `/bi/dashboard/{id}/draft`、PUT `/bi/dashboard/{id}` | 草稿读取/更新 |
| POST `/bi/dashboard/{id}/publish`、`/unpublish` | 提交 `{ "version": N }` 发布或下线 |
| GET `/bi/dashboard/{id}/view` | 获取已发布 manifest、revision 和组件布局 |
| POST `/bi/dashboard/{id}/panels/{key}/data?revision=N` | 仅查询当前发布快照绑定的组件 |
| DELETE `/bi/dashboard/{id}` | 逻辑删除及释放引用 |
| GET `/bi/dashboard/principals`、GET/POST `/{id}/grants`、DELETE 对应授权 | 主体选择和看板资源授权 |

草稿模型示例：

```json
{
  "version": 0,
  "definition": {
    "schemaVersion": 1,
    "name": "城市概览",
    "panels": [
      {"key": "cities", "chartId": 123, "title": "城市数量", "x": 0, "y": 0, "w": 6, "h": 8}
    ]
  }
}
```

chartId 须替换为实际有权查询的新版图表。组件 key 为 1～64 位字母、数字、下划线或横线；名称和标题不超过 200 字符。布局数值、重复 key、重叠、整数越界和版本均在后端校验。

纯使用者不读取草稿。列表显示发布时的名称，不泄漏后续草稿改名；manifest 不返回 chartId、datasetId、字段来源、查询树或过滤值。组件数据仅返回允许的列/行及展示别名，不返回 SQL、参数或数据集名称。底层取数异常对使用者采用通用错误，详细异常留在服务器日志。

组件查询最多并发 2 个；页面刷新或切换看板会丢弃过期响应。查看端在窄屏按布局顺序转为单列，编辑端保留横向画布及数值布局控件。当前不支持客户端传入交互过滤、外部参数、匿名分享或嵌入式免登录访问。
